# ที่เก็บไฟล์และรูปภาพใช้ S3 API มาตรฐานด้านหลัง Interface

ไฟล์และรูปภาพเก็บผ่านที่เก็บไฟล์แบบ S3 API มาตรฐาน โดย Service เรียกผ่าน Interface ไม่ผูกกับผลิตภัณฑ์ตัวใดตัวหนึ่ง เดิมตั้งใจใช้ MinIO บน Docker แต่ตรวจเมื่อ 2026-10-18 พบว่า README ทางการของ MinIO ระบุว่า "THIS REPOSITORY IS NO LONGER MAINTAINED" และที่เก็บถูก archive เมื่อ 25 เม.ย. 2026 พร้อมประกาศว่าฉบับ Community จะไม่มีไบนารีที่คอมไพล์ไว้ให้อีก (ต้อง build จากซอร์สเอง) จึงไม่ใช้ MinIO เป็นฐาน ผู้ใช้ตัดสินใจเลือกทางเดียวกันนี้ ตัวที่เก็บจริงที่รันบน Docker ได้ยังไม่ได้เลือก (ตัดสินใน ticket Architecture decisions 023)

## Considered Options

- MinIO build จากซอร์สเอง: ไม่มีแพตช์ความปลอดภัยใหม่ ความเสี่ยงตกเป็นของเรา
- AIStor Free ของ MinIO: ยังไม่ได้อ่านเงื่อนไขใบอนุญาต
- Amazon S3 โดยตรง: ผู้ใช้ไม่ได้เลือก (ตอบว่าใช้ S3 API มาตรฐาน)

## (อัปเดตภายหลัง 2026-10-19) SeaweedFS เป็นตัวเลือกจาก PoC และเปิดไฟล์ผ่าน Backend ใน v1

**[ตัดสินใจ]**

- ใช้ Interface S3 มาตรฐาน (ไม่เปลี่ยน)
- เลือก SeaweedFS 4.48 (โหมด `weed mini` บน Docker เครื่องเดียว, Apache-2.0) เป็นระบบเก็บไฟล์สำหรับ v1 และเป็นฐานพัฒนา ตัวเลือกนี้ได้จาก PoC บน branch `prototype/seaweedfs-s3` (commit `c6f9eee`) โดยมีเงื่อนไขก่อน Production ด้านล่าง **ไม่ใช่ข้อสรุปว่าพร้อมใช้งานจริงแล้ว**
- v1 เปิดไฟล์ให้ผู้ใช้ผ่าน Backend แบบสตรีมทุกครั้ง ไม่ใช้ Presigned URL ใน v1 เพราะต้องตรวจสิทธิ์ (เจ้าของ, Share Link, จำกัดด้วย email, Trash, Merge) ทุกคำขอ ส่วน Presigned URL ที่ทดสอบพบว่าถอนไม่ได้จนหมดอายุ ใครมี URL ก็โหลดได้ด้วย HTTP ธรรมดา และต้องเปิด S3 สู่ภายนอก (reverse proxy ที่รักษา Host หรือตั้ง `S3_EXTERNAL_URL` และตั้ง CORS) เปลี่ยนเป็น Presigned URL ทีหลังได้โดยแก้หลัง Interface
- สัญญา Interface: การลบไฟล์ที่ไม่มีอยู่ถือว่าสำเร็จ (SeaweedFS ตอบ 204) ลบไฟล์ได้เมื่อไม่มี Block อ้างถึงเท่านั้น (นับ Note ใน Trash, Note ที่ Merge, ฉบับ Undo ตาม product-spec หัวข้อ 9) และมีช่วงผ่อนผันก่อนเก็บกวาดไฟล์ที่อัปโหลดแล้วแต่ยังไม่ถูกอ้างถึง ตารางและอัลกอริทึมใน PoC เป็นภาพร่าง ไม่ใช่ดีไซน์สุดท้าย
- ตรวจกับกฎ Share Link (ticket 009): การให้ Backend ตรวจสิทธิ์ทุกคำขอเปิดไฟล์ไม่ขัดกับกฎเดิม ส่วนผู้รับ Link ดาวน์โหลดไฟล์แนบได้หรือไม่ ยังไม่ได้ตัดสิน (OQ-7)

**ตัวเลือกที่ไม่เลือก:** Garage (AGPL-3.0 ยังไม่ได้ตรวจใบอนุญาตและเวอร์ชันล่าสุดจากหน้าทางการ), RustFS (ฉบับเสถียร 1.0 ออกเดือนกันยายน 2026 ยังใหม่)

**[เงื่อนไขก่อน Production]** (ยังไม่เสร็จทั้งหมด)

1. ตั้งค่าตาม ADR 0008 ครบ รวมการปิดพอร์ตสู่โฮสต์ทั้งหมด (ชุด C ยังเปิด `127.0.0.1:8333` เฉพาะเพื่อทดสอบ) และทดสอบบน Linux จริงที่จะใช้งาน
2. ตัวเตือนความหมดอายุใบรับรอง และทดสอบ healthcheck ขณะใบรับรองหมดอายุ
3. งานเก็บกวาด multipart ที่ค้างและไฟล์ไม่มีผู้อ้างถึง (กำหนดช่วงเวลา) และเผื่อพื้นที่ดิสก์เพราะพื้นที่คืนช้า
4. ขั้นตอนสำรอง/กู้คืนเป็นลายลักษณ์อักษร (รวมไฟล์ตั้งค่า ใบรับรอง และคีย์ ซึ่งไม่อยู่ใน volume)
5. ทดสอบการส่งไฟล์ผ่าน Backend กับเบราว์เซอร์จริง, Range, ไฟล์ใหญ่ และการใช้หน่วยความจำ
6. ตัดสิน OQ-3 (ขนาดไฟล์ภาพ) และ OQ-7 แล้วทดสอบที่ขนาดนั้น

**[ยังไม่ได้ทดสอบ]** บริการ IAM ของ filer ผ่าน gRPC เรียกตรงๆ, healthcheck ขณะใบรับรองหมดอายุ, Linux จริง, ใบรับรองรีโหลดเองเมื่อรอนานกว่า 15 วินาที, ผลต่อความเร็วของ mTLS, ไฟล์ใหญ่กว่า 50 MB, HTTPS reverse proxy หน้า S3, การดาวน์โหลดจากเบราว์เซอร์จริง, การรันหลายเครื่อง/SeaweedFS รุ่นอื่น, การเริ่มเองของคอนเทนเนอร์หลังโปรแกรมล่มจริง (ทดสอบแค่ `docker kill` แล้วสั่งเริ่มด้วยมือ)

ความปลอดภัยและใบรับรองดู ADR 0008
