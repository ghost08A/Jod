# เนื้อหา Block ของ 1 Note เก็บเป็นเอกสาร JSON ก้อนเดียว

เนื้อหาทั้งหมดของ Note (Block ซ้อนกันทุกชั้น) เก็บเป็น `jsonb` ก้อนเดียวใน PostgreSQL โครงสร้างเป็นของ Jod เอง ไม่ผูกกับรูปแบบของ TipTap และทุก Block มีรหัสประจำตัวคงที่ (ไว้เทียบทีละ Block ในหน้าตรวจผล AI) ตัดสินเมื่อ 2026-10-19 เพราะทำให้ Autosave เป็นการเขียนก้อนเดียว ฉบับ Undo เป็นการคัดลอกก้อนเดียว Merge เป็นการต่อ list และตรวจบันทึกชนกันได้ด้วยเลขเวอร์ชันตัวเดียว การแยก 1 Block ต่อ 1 แถวถูกปฏิเสธเพราะ Autosave ต้องเขียนและเรียงลำดับ/ระดับการซ้อนหลายแถวทุกครั้ง ย้ายโครงสร้างทีหลังต้องเขียนข้อมูลทั้งหมดใหม่

## Consequences

- มีตารางเล็กจดว่า "Note หรือฉบับ Undo ใดอ้างไฟล์ใด" อัปเดตในรอบบันทึกเดียวกับเนื้อหา ใช้ตอบกฎ "ลบไฟล์เมื่อไม่มี Block ใดอ้างถึง" (นับ Note ใน Trash, ฉบับ Undo ที่ยังเก็บอยู่ และ Note ที่ Merge ไปแล้ว)
- ไม่มีตารางย้อนดู "ใครชี้มาที่ Note นี้" สำหรับ Reference Card เพราะไม่มี Requirement (การ์ดชี้ตัวตน Note, Merge ตาม Alias) เพิ่มได้ภายหลัง
- ตรวจบันทึกชนกันด้วยเลขเวอร์ชันต่อ Note เพิ่มทีละ 1 ทุกครั้งที่บันทึก (ครอบคลุม Title เนื้อหา Context) แท็บส่งเลขที่ตนเห็นมา ไม่ตรง = ชนกัน การย้ายใน Tree ไม่นับ ไม่มีช่องทางส่งข่าวสดข้ามแท็บใน v1
- ฉบับ Undo (หลังยืนยันผล AI จัดโครงสร้าง) เก็บฉบับล่าสุดฉบับเดียวต่อ Note อายุ 30 วันแล้วระบบลบเอง ลบ Note ถาวรลบฉบับ Undo ด้วย ถ้าแก้เพิ่มหลัง AI จัด Undo ยังทำได้ แต่ต้องแจ้งผู้ใช้ว่าส่วนที่พิมพ์เพิ่มจะหาย
- (อัปเดตภายหลัง 2026-10-19) ต้องมีตารางการ์ดทิศไปข้างหน้า (Note ใดมีการ์ดชี้ไป Note ใด) อัปเดตในรอบบันทึกเดียวกับเนื้อหา เพื่อคำนวณเซต Note ที่ Share Link เปิดได้ (ticket 009) ข้อความข้างบนที่ว่าไม่มีตารางสำหรับ Reference Card ยังถูกต้องสำหรับทิศย้อนกลับ (ใครชี้มาที่ Note นี้)
