# to-spec 1a: โครงระบบและบัญชีผู้ใช้ (Google Sign-In)

สถานะ: **โค้ดตาม spec นี้ทำครบแล้วทั้ง backend และหน้าเว็บ (Google Sign-In วิธีเดียว ถอดเส้นทางรหัสผ่านแล้ว) ตรวจด้วยเทสต์อัตโนมัติที่ใช้ตัวตรวจ token ปลอม ยังไม่ปิด 1a:** เหลือตรวจด้วยมือกับ Google จริง (เกณฑ์ข้อ 17) และให้ CI บน GitHub ผ่าน (เกณฑ์ข้อ 19 ข้อ ง)

ป้ายกำกับในเอกสารนี้

- **[ตัดสินแล้ว]** ผู้ใช้ยืนยันแล้ว (อ้างแหล่ง)
- **[ร่าง]** ผู้ช่วยเสนอ ยังไม่ใช่ Decision จนกว่าผู้ใช้อนุมัติไฟล์นี้
- **[ยังไม่ได้ตรวจ]** ข้อเท็จจริงที่ยังไม่มีหลักฐานทดสอบ

## 0. ที่มาและหลักฐาน

- ขอบเขต 1a กำหนดโดยผู้ใช้: บัญชีผู้ใช้ Authentication/Authorization, PostgreSQL, Docker Compose และ CI ส่วน 1b (Note พื้นฐาน, Block schema ขั้นต่ำ, Autosave, ตรวจบันทึกชนกัน, Editor บนเดสก์ท็อปและมือถือ) แยกเป็น to-spec ของตัวเอง งานช่วง 1c เดิม (ยืนยันอีเมล/ลืมรหัสผ่าน) **ยกเลิกแล้ว** เพราะใช้ Google Sign-In
- **การตัดสินใจ 2026-10-20 (ผู้ใช้):** Jod ใช้ Google Sign-In เป็นวิธีเดียว ไม่รองรับ email + รหัสผ่านที่ Jod จัดการเอง Backend ต้องตรวจ Google ID token เอง ใช้ Google `sub` ระบุตัวตน ตรวจ `email_verified` จาก token ที่ตรวจแล้ว และห้ามเชื่อข้อมูลตัวตนจากหน้าเว็บ ต้องจำกัดผู้เข้าร่วมให้เหมาะกับกลุ่มปิด ส่วนที่ใช้ต่อได้คือ Session, JWT, Refresh token, คุกกี้ และการป้องกัน CSRF
- **กติกาตรวจ ID token ตามเอกสาร Google (ตรวจ 2026-10-20 จาก <https://developers.google.com/identity/gsi/web/guides/verify-google-id-token>):** ตรวจลายเซ็นด้วยกุญแจสาธารณะของ Google (กุญแจหมุนเวียน แคชตาม Cache-Control), `aud` ตรง Client ID ของเรา, `iss` เป็น `accounts.google.com` หรือ `https://accounts.google.com`, `exp` ไม่หมด, `hd` มีเมื่อเป็นบัญชี Workspace, ใช้ `sub` เป็นตัวระบุตัวตน (ไม่ซ้ำและไม่ถูกนำกลับมาใช้) อีเมลเปลี่ยนได้จึงห้ามใช้เป็นกุญแจ และ Google เป็นผู้ยืนยันอีเมลที่เชื่อถือได้เฉพาะ Gmail กับบัญชี Workspace (ที่มี `hd`) เอกสารแนะนำให้ใช้ไลบรารีของ Google หรือไลบรารี JWT ทั่วไป ไม่เขียนตรวจเอง และหน้าที่ตรวจไม่ได้พูดถึง nonce
- Vite proxy `/api` ไป `http://localhost:5133` (หน้าเว็บกับ API เป็นแหล่งเดียวกันตอนพัฒนา) Vitest ตั้ง `environment: 'node'` ทดสอบตรรกะล้วนได้ ทดสอบ component ใน DOM ไม่ได้ (ยังไม่มี jsdom)
- .NET 8 หมดซัพพอร์ต 2026-11-10 ส่วน .NET 10 (LTS) ถึง 2028-11-14 จึงมี ADR 0010
- Web Locks API ใช้ได้ทั่วไปตั้งแต่ มี.ค. 2022 แต่เฉพาะบริบทที่ปลอดภัย (HTTPS หรือ localhost) (MDN)
- `Google.Apis.Auth` รุ่น 1.77.0 (Apache-2.0) มีชุดไบนารีสำหรับ net6.0 และ netstandard2.0 ตามข้อมูล NuGet ผู้ใช้เลือกใช้เมื่อ 2026-10-20 ทดลองแล้ว 2026-10-21: build บน .NET 10 ผ่านและปฏิเสธ token ผิดรูปแบบ/ลายเซ็นปลอมได้ **[ยังไม่ได้ตรวจ]** กับ token ที่ Google เซ็นจริง

## 2. Confirmed Decisions ที่ 1a ใช้

**จากเอกสารเดิมที่ยังมีผล**

- **[ตัดสินแล้ว]** Access token (JWT ที่ Jod ออกเอง) 15 นาทีในหน่วยความจำ + Refresh token 30 วันในคุกกี้ HttpOnly/Secure/SameSite หมุนทุกครั้ง เก็บค่าแฮชในฐานข้อมูล เพิกถอนได้ ตรวจจับการใช้ใบเก่าซ้ำ ไม่มีช่วงผ่อนผันฝั่งเซิร์ฟเวอร์ ฝั่งหน้าเว็บประสานหลายแท็บให้มีคำขอ Refresh เดียว (ADR 0006)
- **[ตัดสินแล้ว]** ทุก Note เป็นของเจ้าของคนเดียว ตรวจเจ้าของฝั่งเซิร์ฟเวอร์ทุกครั้ง (ADR 0006)
- **[ตัดสินแล้ว]** PostgreSQL (ADR 0004) EF Core อยู่ใน `Jod.Service` Web → Service → Domain ห้ามย้อน ใช้ `CustomError` สำหรับข้อผิดพลาดทางธุรกิจ (`backend/CLAUDE.md`)
- **[ตัดสินแล้ว]** ผู้ใช้เห็นข้อความเข้าใจง่ายพร้อมรหัสอ้างอิง log ไม่เก็บเนื้อหา/อีเมล/โทเคน (spec หัวข้อ 12, ticket 015)
- **[ตัดสินแล้ว]** ความลับอยู่นอก git: dev ใช้ `appsettings.Development.json` (ไม่ commit) Production ใช้ตัวแปรสภาพแวดล้อมหรือระบบจัดการความลับ ผู้ใช้เป็นคนใส่ความลับจริงเอง (CLAUDE.md, ticket 023)
- **[ตัดสินแล้ว]** ธีมมืดเท่านั้น Responsive Web ใช้ได้ทั้งเดสก์ท็อปและมือถือ (ticket 019)
- **[ตัดสินแล้ว]** .NET 10 LTS เป็นเป้าของ backend (ADR 0010)

**การตัดสินใจ 2026-10-20 (ผู้ใช้)**

- **[ตัดสินแล้ว]** Google Sign-In เป็นวิธียืนยันตัวตนวิธีเดียว ไม่มีรหัสผ่าน ไม่มีลิงก์ยืนยัน/รีเซ็ต Jod ไม่ส่งอีเมล (ADR 0006, ticket 014)
- **[ตัดสินแล้ว]** Backend ตรวจ ID token เอง ใช้ `sub` ระบุตัวตน ตรวจ `email_verified` ไม่เชื่อข้อมูลตัวตนจากหน้าเว็บ
- **[ตัดสินแล้ว]** ต้องจำกัดผู้เข้าร่วมให้เหมาะกับกลุ่มปิด ห้ามเปิดสมัครสาธารณะโดยไม่ตั้งใจ (วิธีที่เสนออยู่ในหัวข้อ 8)

**ที่ผู้ใช้ยืนยันไว้ก่อนหน้า ไม่เกี่ยวกับวิธียืนยันตัวตน (Q1, Q3–Q6, Q9–Q11)**

## 3. Requirements [ร่าง]

- R1 เข้าสู่ระบบด้วยบัญชี Google ได้ (เฉพาะผู้ที่อยู่ในรายชื่ออนุญาต ดูหัวข้อ 8)
- R2 ออกจากระบบได้ อยู่ในระบบต่อได้โดยไม่ต้องล็อกอินใหม่ภายใน 30 วัน
- R3 ส่วนที่ต้องล็อกอินเข้าไม่ได้ถ้ายังไม่ล็อกอิน
- R4 ข้อความผิดพลาดเป็นภาษาไทยเข้าใจง่ายพร้อมรหัสอ้างอิง
- R5 ใช้ได้บนมือถือและเดสก์ท็อป
- R6 คนที่ไม่ได้รับอนุญาตเข้าไม่ได้ แม้มีบัญชี Google ที่ถูกต้อง

## 4. User Flows [ร่าง]

| # | เส้นทาง | ขั้นตอนสำคัญ |
|---|---|---|
| F1 | เข้าสู่ระบบด้วย Google | กดปุ่ม Google → เลือกบัญชี → หน้าเว็บส่ง credential ให้ Backend → ตรวจ token → อยู่ในรายชื่อ → เข้าระบบทันที (ผู้ใช้ใหม่ถูกสร้างอัตโนมัติจากข้อมูลใน token) ถ้าไม่อยู่ในรายชื่อเห็น "บัญชี Google นี้ยังไม่ได้รับอนุญาตให้ใช้ Jod" ถ้า token ใช้ไม่ได้หรืออีเมลไม่ได้รับการยืนยันเห็นข้อความทั่วไปพร้อมรหัสอ้างอิง |
| F2 | เปิดหน้าใหม่หรือรีเฟรช | หน้าเว็บขอ Access token ใหม่เงียบๆ ด้วยคุกกี้ ถ้าไม่ได้ → ไปหน้าเข้าสู่ระบบ |
| F3 | Access token หมดอายุกลางการใช้งาน | ต่ออายุเงียบๆ แล้วลองคำขอเดิมซ้ำ 1 ครั้ง ถ้าต่ออายุไม่ได้ → หน้าเข้าสู่ระบบพร้อมข้อความ |
| F4 | เปิดหลายแท็บ | ใช้ Web Locks ให้มีคำขอต่ออายุเดียวต่อรอบ แท็บอื่นรับผลผ่าน BroadcastChannel |
| F5 | ออกจากระบบ | เพิกถอน Refresh token ชุดนั้น ลบคุกกี้ กลับหน้าเข้าสู่ระบบ แท็บอื่นออกตาม |
| F6 | พบการใช้ Refresh token ใบเก่าซ้ำ | เพิกถอนทั้งชุด ผู้ใช้ถูกบังคับล็อกอินใหม่ |
| F7 | ผู้ดูแลเอาอีเมลออกจากรายชื่อ | การต่ออายุครั้งถัดไปถูกปฏิเสธและเพิกถอนทั้งชุด ผู้ใช้เสียสิทธิ์ภายใน 15 นาที |
| F8 | ข้อผิดพลาดของระบบ | เห็นข้อความทั่วไป + รหัสอ้างอิง ไม่เห็นรายละเอียดภายใน |

## 5. Business Rules

**[ตัดสินแล้ว]**

- ตัวตนคือ Google `sub` อีเมลไม่ใช่กุญแจและเปลี่ยนได้ (ผู้ใช้ 2026-10-20, เอกสาร Google)
- รับเฉพาะ ID token ที่ผ่านการตรวจฝั่ง Backend ครบ (ลายเซ็น, `aud`, `iss`, `exp`) และ `email_verified` เป็นจริง ข้อมูลตัวตนที่หน้าเว็บส่งมานอกจาก credential ถูกเมิน
- Access token อายุ 15 นาที Refresh token อายุ 30 วัน หมุนทุกครั้ง ใช้ใบเก่าซ้ำ = เพิกถอนทั้งชุด ไม่มีช่วงผ่อนผันฝั่งเซิร์ฟเวอร์ เวลาเหลื่อมที่ยอมของ Access token 30 วินาที
- จำกัดอัตราต่อ IP แยก 2 โควตา: เข้าสู่ระบบ 10 คำขอ/นาที และต่ออายุ 60 คำขอ/นาที (ค่าเป็นค่าตั้งค่า) เพราะการต่ออายุเงียบทำทุกครั้งที่เปิดหน้า ไม่ควรแย่งโควตาของการเข้าสู่ระบบ

**[ร่าง]**

- ผู้ใช้ใหม่ถูกสร้างเมื่อ token ผ่านและอีเมลอยู่ในรายชื่ออนุญาต ผู้ใช้เดิม (พบ `sub` ผูกอยู่แล้ว) อัปเดตอีเมลเป็นค่าล่าสุดจาก token ทุกครั้งที่เข้าสู่ระบบ ไม่เก็บชื่อหรือรูปโปรไฟล์ (ยังไม่มีความต้องการ)
- ถ้า `email_verified` เป็นเท็จ หรือ (ไม่มี `hd` และอีเมลไม่ลงท้าย `@gmail.com`) ปฏิเสธ 401 ตามคำแนะนำของ Google ว่าเชื่อถือการยืนยันอีเมลได้เฉพาะ Gmail และ Workspace (OQ-11)
- อีเมลเทียบกับรายชื่อแบบไม่สนตัวพิมพ์เล็กใหญ่และตัดช่องว่างหัวท้าย
- Access token claims: `sub` (รหัสผู้ใช้ใน Jod ไม่ใช่ Google `sub`) `jti` `iat` `exp` `iss` `aud` ไม่ใส่อีเมล เซ็นแบบ HS256 ด้วยกุญแจลับความยาวอย่างน้อย 32 ไบต์จากการตั้งค่า (เหมือนเดิม)
- ออกจากระบบเพิกถอนเฉพาะ "ชุด" ของอุปกรณ์นั้น Access token ที่ออกไปแล้วยังใช้ได้จนหมดอายุ (≤15 นาที) เป็นข้อจำกัดของ JWT ไม่ใช่บั๊ก
- ไม่เก็บและไม่เขียน log ซึ่ง Google ID token

**Email ที่ยังมีอยู่ใน Jod (เป็นข้อมูล ไม่ใช่วิธีล็อกอิน)**

แยกให้ชัด: Jod **ใช้ email เป็นข้อมูล** แต่ **ไม่จัดการรหัสผ่านและไม่ส่งอีเมลใดๆ เอง** (ไม่มีอีเมลยืนยัน ลืมรหัสผ่าน หรือแจ้งเตือน)

| ที่ที่ email ยังใช้ | ใช้อย่างไร | ทำไมยังจำเป็น |
|---|---|---|
| รายชื่ออีเมลที่อนุญาต (หัวข้อ 8) | เทียบกับ email ที่ Google ยืนยันแล้วใน token | จำกัดผู้เข้าร่วมกลุ่มปิด |
| แสดงในหน้า "บัญชีของฉัน" และ `GET /api/me` | ข้อมูลล่าสุดจาก token ตอนเข้าสู่ระบบ | ให้ผู้ใช้ยืนยันว่าเข้าบัญชีถูกคน |
| Share Link แบบ "จำกัดด้วย email" (ฟีเจอร์ในอนาคต ticket 009) | ผู้รับต้องเข้าสู่ระบบด้วย Google ที่ email ซึ่ง Google ยืนยันแล้วตรงกับที่ผู้แชร์ระบุ | ฟีเจอร์ยังเป็นความต้องการ ผู้รับที่ไม่ใช่สมาชิกรอ OQ-15 |
| ห้ามอยู่ใน log | email ไม่ถูกเขียนลง log | กฎความปลอดภัยเดิม |

email **ไม่ใช่ตัวระบุบัญชี** (ใช้ Google `sub`) และ Jod ไม่ส่งอีเมลหาใคร

**Security Rules (สรุปรวม)**

1. ตรวจ Google ID token ที่ Backend ทุกครั้งและครบ: ลายเซ็น (กุญแจของ Google แคชตามที่ Google ระบุ), `aud`, `iss`, `exp`, `email_verified` ห้ามเชื่อข้อมูลตัวตนจากหน้าเว็บ
2. ตัวตนคือ Google `sub` เท่านั้น email เป็นข้อมูลที่อัปเดตตาม token
3. กลุ่มปิด: ไม่อยู่ในรายชื่อ = เข้าไม่ได้ รายชื่อว่าง = ไม่มีใครเข้าได้ ไม่มีโหมดเปิดสมัคร ตรวจทั้งตอนเข้าสู่ระบบและตอนต่ออายุ
4. คำขอที่ตั้งหรือใช้คุกกี้ (`/api/auth/google`, `refresh`, `logout`) ต้องมีหัวข้อ `X-Requested-With: jod` และคุกกี้เป็น HttpOnly, SameSite=Strict, Path แคบ, Secure นอก Development
5. Access token อยู่ในหน่วยความจำเท่านั้น (ไม่อยู่ใน localStorage/sessionStorage) Refresh token เก็บเป็นค่าแฮชในฐานข้อมูล หมุนทุกครั้ง ใช้ซ้ำ = เพิกถอนทั้งชุด
6. ไม่เก็บ Google ID token ในฐานข้อมูล ไม่เขียน ID token, Access token, Refresh token หรือ email ลง log และไม่ใส่ในคำตอบ error
7. จำกัดอัตราต่อ IP แยก 2 โควตา (เข้าสู่ระบบ 10/นาที, ต่ออายุ 60/นาที)
8. ความลับ (กุญแจเซ็น Access token) อยู่นอก git แอปไม่เริ่มถ้ากุญแจหาย/สั้น/เป็นค่าสมมติ `Google:ClientId` ไม่ใช่ความลับ

## 7. Data Model ระดับที่จำเป็น [ร่าง]

| ตาราง | ฟิลด์สำคัญ | หมายเหตุ |
|---|---|---|
| ผู้ใช้ (`AppUser`, ตารางเรียบง่ายใหม่ ไม่ใช้ ASP.NET Core Identity) | รหัส (Guid), Google `sub` (ไม่ซ้ำ มี unique index), อีเมล (ค่าล่าสุดจาก token), วันที่สร้าง | ผู้ใช้ตัดสินเลือกทางเลือก B เมื่อ 2026-10-20 ไม่มีคอลัมน์รหัสผ่าน/ล็อกบัญชี ชื่อคอลัมน์เป็นร่าง ต้องขอยืนยันก่อนทำ migration |
| Refresh token (`RefreshToken`) | รหัส, รหัสผู้ใช้, รหัสชุด (family), ค่าแฮช SHA-256 ของโทเคนสุ่ม 256 บิต, สร้างเมื่อ, หมดอายุเมื่อ, ถูกใช้แล้วเมื่อ, เพิกถอนเมื่อ, ถูกแทนที่โดย | ไม่เก็บโทเคนจริง (เหมือนเดิม) |

- ตาราง Identity เดิม (`AspNet*` รวม `PasswordHash`, `SecurityStamp`, `AccessFailedCount`, `LockoutEnd` และ `AspNetUserLogins`) ถูกแทนที่ด้วยตารางผู้ใช้ข้างบน ตรวจแล้วว่าไม่มีฟีเจอร์อื่นใช้ (ยังไม่มี Note/Share) แทนที่แล้วด้วย migration เดียว (`InitialCreate` สร้างใหม่ ไม่ใช่เพิ่มตัวที่สอง เพื่อไม่ให้ชื่อตาราง Identity ค้างในประวัติ migration) ทำก่อนมีตาราง Note ฐานข้อมูลพัฒนาที่สร้างจากรุ่นแรกต้องลบแล้วสร้างใหม่ (README)
- กติกาการใช้ Refresh token ต้องเป็นขั้นตอนเดียวในฐานข้อมูล: อัปเดตแบบมีเงื่อนไข "ยังไม่ถูกใช้" แล้วดูว่ากระทบ 1 แถวหรือไม่ ถ้าไม่ (ถูกใช้ไปแล้ว) ถือว่าใช้ซ้ำ → เพิกถอนทั้งชุด คำขอต่ออายุพร้อมกันสองคำขอด้วยโทเคนใบเดียวกัน หนึ่งสำเร็จ อีกหนึ่ง 401 และทั้งชุดถูกเพิกถอน (เหมือนเดิม)
- ยังไม่มีงานล้างโทเคนหมดอายุ (เลื่อนไปก่อน Production) ตาราง Note ยังไม่สร้างใน 1a ความเป็นเจ้าของของ Note ใช้ `OwnerId` (Guid) ใน 1b
- การสร้าง/แก้ schema ในงานนี้ทำได้เพราะ to-spec นี้เป็นคำขอที่ชัดเจนตามกฎใน `backend/CLAUDE.md` migration ใช้ EF Core เก็บใน `Jod.Service`

## 8. การควบคุมผู้เข้าร่วม (กลุ่มปิด) [ร่าง รอผู้ใช้อนุมัติ]

เป้าหมาย: ล็อกอินด้วย Google สำเร็จไม่ได้แปลว่าเข้า Jod ได้ และไม่มีทางเปิดสาธารณะโดยไม่ตั้งใจ

- **รายชื่ออีเมลที่อนุญาต** ค่าตั้งค่า `Access:AllowedEmails` (รายการอีเมล) ใน Backend แก้โดยผู้ดูแลที่เข้าถึงเซิร์ฟเวอร์/ตัวแปรสภาพแวดล้อม ไม่มีหน้าจัดการใน v1 (OQ-12)
- **ค่าเริ่มต้นคือไม่อนุญาตใคร** รายชื่อว่างหรือไม่ตั้ง = ไม่มีใครเข้าได้ ไม่มีโหมด "เปิดสมัครสาธารณะ" ในทุกสภาพแวดล้อม (ยกเลิกค่า `Registration:Mode` และกฎ Open ใช้ได้เฉพาะ Development/Test ของโค้ดรุ่นแรก)
- ตรวจรายชื่อตอนเข้าสู่ระบบ (ทั้งผู้ใช้ใหม่และเดิม) และตอนต่ออายุ ถ้าไม่อยู่ในรายชื่อ ตอบ 403 ตอนเข้าสู่ระบบ ส่วนตอนต่ออายุตอบ 401 และเพิกถอนทั้งชุด
- ตอนเริ่มแอป: แอปไม่เริ่มถ้า `Google:ClientId` หาย หรือยังเป็นค่าสมมติ หรือมีรายการในรายชื่อที่ไม่ใช่อีเมลที่ถูกต้อง รายชื่อว่างเริ่มได้แต่เขียน log เตือนว่า "ไม่มีใครเข้าได้"
- ตอบ 403 (ไม่ใช่ 401) เมื่อ token ถูกต้องแต่ไม่อยู่ในรายชื่อ เพื่อให้ผู้ใช้รู้ว่าต้องติดต่อผู้ดูแล (เป็นข้อมูลที่กลุ่มเพื่อนรู้กันอยู่แล้ว)
- เทสต์อัตโนมัติ: รายชื่อว่าง = ไม่มีใครเข้าได้, อีเมลไม่อยู่ในรายชื่อ → 403, ตัวพิมพ์/ช่องว่างไม่เป็นปัญหา, เอาออกจากรายชื่อแล้วต่ออายุไม่ได้, `Google:ClientId`/รายการผิดรูปแบบ → แอปไม่เริ่ม
- compose ผูกพอร์ตกับ `127.0.0.1` เท่านั้น และไม่มี compose/Dockerfile สำหรับ Production ใน 1a (เหมือนเดิม)

## 9. API Contract [ร่าง]

ทุก endpoint อยู่ใต้ `/api` ตอบ JSON คุกกี้ Refresh ชื่อ `jod_refresh` (HttpOnly, SameSite=Strict, Path=`/api/auth`, อายุ 30 วัน, Secure ในทุกสภาพแวดล้อมที่ไม่ใช่ Development ส่วน Development ใช้ Secure ตามโปรโตคอลของคำขอ) คำขอที่ตั้งหรือใช้คุกกี้ต้องมีหัวข้อ `X-Requested-With: jod`

| Endpoint | เข้าได้ | คำขอ | ผลสำเร็จ | ข้อผิดพลาดหลัก |
|---|---|---|---|---|
| `POST /api/auth/google` | ไม่ต้องล็อกอิน (ต้องมีหัวข้อ) | `{ credential }` (Google ID token) | 200 `{ accessToken, expiresInSeconds, user:{id,email} }` + คุกกี้ | 400 ไม่มี credential, 401 token ใช้ไม่ได้/อีเมลไม่ยืนยัน, 403 ไม่อยู่ในรายชื่อหรือไม่มีหัวข้อ, 429 |
| `POST /api/auth/refresh` | ใช้คุกกี้ + หัวข้อ | ไม่มี body | 200 รูปแบบเดียวกับ `/api/auth/google` + คุกกี้ใหม่ | 401 ไม่มี/หมดอายุ/เพิกถอน/ใช้ซ้ำ/ไม่อยู่ในรายชื่อแล้ว (ใช้ซ้ำและไม่อยู่ในรายชื่อเพิกถอนทั้งชุด), 403 ไม่มีหัวข้อ |
| `POST /api/auth/logout` | ใช้คุกกี้ + หัวข้อ | – | 204 + ลบคุกกี้ | 403 ไม่มีหัวข้อ (ไม่มีคุกกี้ก็ 204 ซ้ำได้) |
| `GET /api/me` | ต้องล็อกอิน | – | 200 `{ id, email }` | 401 |

- ไม่มี `register`, `login` และฟิลด์ `emailConfirmed` อีกต่อไป (ทุกบัญชีผ่านการยืนยันจาก Google)
- **รูปแบบ error ทุก endpoint:** `application/problem+json` มี `status`, `title`, `detail` (ข้อความไทยที่ผู้ใช้เห็นได้), `reference` (รหัสสั้นสุ่ม 8 ตัวอักษร ใช้ค้นใน log), `errors` (รายการข้อความจาก `CustomError`) ไม่มี stack trace หรือชื่อภายใน
- คนที่ยังไม่ล็อกอินเรียกเส้นทางที่ไม่มีหรือใช้วิธีผิด ได้ 401 (ผลจากนโยบาย "ทุกอย่างต้องล็อกอิน")
- header ความปลอดภัยพื้นฐาน ไม่เปิด CORS (หน้าเว็บกับ API แหล่งเดียวกัน) ชื่อฟิลด์ JSON เป็น camelCase

### Error Cases (ผู้ใช้เห็นข้อความไทยเสมอ พร้อมรหัสอ้างอิง `reference` ที่ตรงกับ log)

| เหตุการณ์ | สถานะ | ข้อความที่ผู้ใช้เห็น (ร่าง) | หมายเหตุ |
|---|---|---|---|
| `/api/auth/google` ไม่มี body หรือไม่มี credential | 400 | ข้อมูลที่ส่งมาไม่ถูกต้อง | |
| ไม่มีหัวข้อ `X-Requested-With: jod` (google/refresh/logout) | 403 | คำขอไม่ถูกต้อง | |
| ID token ลายเซ็น/`aud`/`iss`/`exp` ผิด หรือรูปแบบผิด | 401 | เข้าสู่ระบบด้วย Google ไม่สำเร็จ ลองอีกครั้ง | ไม่บอกเหตุผลละเอียด log เก็บชนิดความผิด ไม่เก็บ token |
| `email_verified` เป็นเท็จ หรือไม่ใช่ Gmail/ไม่มี `hd` (OQ-11 ตัดสินแล้ว) | 401 | บัญชี Google นี้ใช้เข้า Jod ไม่ได้ (อีเมลยังไม่ได้รับการยืนยันจาก Google หรือไม่ใช่ Gmail/บัญชีองค์กร) | |
| token ถูกต้องแต่อีเมลไม่อยู่ในรายชื่อ | 403 | บัญชี Google นี้ยังไม่ได้รับอนุญาตให้ใช้ Jod ติดต่อผู้ดูแล | รายชื่อว่าง = ได้ข้อความนี้ทุกคน |
| ติดต่อ Google เพื่อดึงกุญแจตรวจลายเซ็นไม่ได้ | 503 (หรือ 500 ทั่วไป ตัดสินตอนลงมือ) | ตรวจสอบกับ Google ไม่ได้ชั่วคราว ลองอีกครั้ง | **ห้ามตอบ 401** เพราะไม่ใช่ความผิดของผู้ใช้ และห้ามให้หน้าเว็บมองเป็น "ออกจากระบบ" ต้องมีชนิด error ใหม่หรือใช้ 500 |
| เกินโควตาเข้าสู่ระบบ (10/นาที/IP) หรือต่ออายุ (60/นาที/IP) | 429 | ส่งคำขอถี่เกินไป กรุณารอสักครู่แล้วลองใหม่ | |
| ต่ออายุ: ไม่มีคุกกี้/หมดอายุ/เพิกถอน/ใช้ซ้ำ | 401 | ต้องเข้าสู่ระบบ | ใช้ซ้ำ = เพิกถอนทั้งชุด |
| ต่ออายุ: อีเมลถูกเอาออกจากรายชื่อแล้ว | 401 | ต้องเข้าสู่ระบบ | เพิกถอนทั้งชุด |
| `GET /api/me` ไม่มีโทเคน/โทเคนเสีย/ผู้ใช้ไม่มีอยู่แล้ว | 401 | ต้องเข้าสู่ระบบ | |
| เส้นทางที่ไม่มีหรือใช้วิธีผิด โดยยังไม่ล็อกอิน | 401 | ต้องเข้าสู่ระบบ | ผลจากนโยบาย "ทุกอย่างต้องล็อกอิน" ล็อกอินแล้วได้ 404/405 |
| ข้อผิดพลาดที่ไม่คาดคิด | 500 | ระบบขัดข้องชั่วคราว ให้แจ้งผู้ดูแลพร้อมรหัสอ้างอิง | log เก็บชนิดและ stack trace ไม่เก็บข้อความ exception |

## 10. Architecture ของ 1a (ใช้โครงเดิม Web → Service → Domain)

- **Web.Jod:** `AuthController` (ล็อกอินด้วย Google, ต่ออายุ, ออก, me), ตั้ง JWT bearer + นโยบายต้องล็อกอินเป็นค่าเริ่มต้น (`[AllowAnonymous]` เฉพาะ endpoint ที่ระบุ), ตัวจัดการข้อผิดพลาดที่สร้าง `reference`, ตัวจำกัดอัตรา 2 โควตา, ตรวจ `Google:ClientId` และรายชื่ออนุญาตตอนเริ่มแอป
- **Jod.Service:** `JodDbContext`, `AuthService` (ตรวจ token ผ่าน `IGoogleIdTokenVerifier`, ตรวจรายชื่อ, หา/สร้างผู้ใช้จากการผูก Google, ออก/หมุน/เพิกถอนโทเคน), ตัวตรวจ ID token จริง (ใช้ `Google.Apis.Auth` ดูข้างล่าง), การตั้งค่าแบบ Options, migrations, `AppUser`
- **Jod.Domain:** `IAuthService`, `IGoogleIdTokenVerifier`, `GoogleSignInRequestModel`, `GoogleIdentity`, `AuthResultViewModel`, `UserViewModel`, `AuthSessionModel`, `CustomError`/`ErrorKind`
- **ทำไม `IGoogleIdTokenVerifier` เป็น interface:** เป็นการเชื่อมต่อภายนอก (เครือข่ายไปหากุญแจของ Google) ตามกฎ `backend/CLAUDE.md` ว่าการเชื่อมต่อภายนอกอยู่ใน Service และเทสต์ต้องแทนด้วยตัวปลอมได้ เพราะเทสต์อัตโนมัติเรียก Google จริงไม่ได้
- **ตัวตรวจ token (ผู้ใช้เลือก 2026-10-20):** ไลบรารีทางการ `Google.Apis.Auth` ลดงานเขียนเอง เสียหนึ่ง dependency (build บน .NET 10 ผ่านแล้ว ยังไม่ได้ตรวจกับ token ที่ Google เซ็นจริง) ทางสำรองถ้าไม่เป็นไปตามคาดคือไลบรารี JWT ที่มีอยู่ (`Microsoft.IdentityModel`) กับกุญแจของ Google ซึ่งต้องเขียนและทดสอบการแคช/หมุนกุญแจเอง
- **ฝั่งหน้าเว็บ:** `modules/auth/` (components, hooks, services, types, utils) ปุ่ม "Sign in with Google" โหลดสคริปต์ Google Identity Services จาก `https://accounts.google.com/gsi/client` และรับ credential ส่งต่อให้ `POST /api/auth/google` Client ID อ่านจาก `VITE_GOOGLE_CLIENT_ID` (ไม่ใช่ความลับ) ส่วน `core/http`, `core/router`, `core/providers` และตัวประสานหลายแท็บใช้ต่อได้ทั้งหมด ตรรกะที่ทดสอบได้ใส่ใน `utils/` เป็น `*.test.ts` (ไม่เพิ่ม jsdom ใน 1a)
- **ธีม:** ใช้ธีมมืดและตัวแปร CSS ที่ทำไว้แล้ว (ตาม ticket 017) `DESIGN.md` เป็นเอกสารอ้างอิงเท่านั้น ไม่ใช่ชุดสีของ Jod

## 12. Acceptance Criteria [ร่าง]

1. เข้าสู่ระบบด้วย Google (ผ่านตัวตรวจ token ปลอมในเทสต์) สำเร็จได้ 200 + Access token + คุกกี้ และมีแถวผู้ใช้กับแถวผูก Google (`sub`) ไม่มี ID token ในฐานข้อมูลหรือ log
2. เข้าสู่ระบบซ้ำด้วย `sub` เดิมได้ผู้ใช้คนเดิม (ไม่สร้างซ้ำ) และอีเมลถูกอัปเดตเมื่อเปลี่ยนใน token
3. token ใช้ไม่ได้ได้ 401: ลายเซ็นผิด, `aud` ผิด, `iss` ผิด, หมดอายุ, รูปแบบผิด, ไม่มี credential (400) และ `email_verified` เป็นเท็จ ข้อมูลตัวตนที่แนบมาใน body นอกจาก credential ถูกเมิน (มีเทสต์ส่งอีเมลปลอมใน body แล้วต้องได้ผู้ใช้ตามที่อยู่ใน token)
4. กลุ่มปิด: รายชื่อว่าง = ไม่มีใครเข้าได้, อีเมลที่ไม่อยู่ในรายชื่อได้ 403 พร้อมข้อความไทย, ตัวพิมพ์เล็กใหญ่/ช่องว่างไม่มีผล, บัญชีที่ไม่ใช่ Gmail และไม่มี `hd` ถูกปฏิเสธ (OQ-11 ตัดสินแล้ว: ไม่รับใน v1)
5. Refresh: ได้ Access token ใหม่ + คุกกี้ใหม่, ใบเก่าใช้ซ้ำ → 401 และทั้งชุดถูกเพิกถอน, คำขอ Refresh พร้อมกัน 2 คำขอด้วยใบเดียวกัน → หนึ่งสำเร็จ อีกหนึ่ง 401 และชุดถูกเพิกถอน, ครบ 30 วัน → 401, เอาอีเมลออกจากรายชื่อแล้วต่ออายุ → 401 และชุดถูกเพิกถอน
6. ออกจากระบบ: Refresh หลังออกใช้ไม่ได้ คุกกี้ถูกลบ ทำซ้ำได้ คุกกี้ถูกต้องตามสเปค (HttpOnly, SameSite=Strict, Path, Secure นอก Development) และ `google`/Refresh/Logout ที่ไม่มี `X-Requested-With` ถูกปฏิเสธ 403
7. `GET /api/me`: ไม่มีโทเคน, หมดอายุ, ลายเซ็นผิด → 401, โทเคนถูกต้อง → 200 และ endpoint ใหม่ใดๆ ที่ไม่ใส่ `[AllowAnonymous]` ถูกบังคับล็อกอินโดยอัตโนมัติ (มีเทสต์)
8. ตอนเริ่มแอป: ไม่มี/สมมติ `Google:ClientId`, รายการอีเมลผิดรูปแบบ, `Jwt:SigningKey` หาย/สั้นกว่า 32 ไบต์/ยังเป็นค่าสมมติ → แอปไม่เริ่ม (มีเทสต์ทุกข้อ) ไม่มีค่าลับใน git
9. ทุกคำตอบผิดพลาดเป็น problem+json มี `reference` ข้อผิดพลาด 500 ไม่รั่ว stack trace และ log มีรหัสอ้างอิง+ชนิดข้อผิดพลาด **ไม่มี** อีเมล โทเคน (ทั้ง Google ID token, Access token, Refresh token) หรือเนื้อหาคำขอ (ทดสอบด้วยการดักล็อก)
10. จำกัดอัตรา: คำขอที่ 11 ของ `/api/auth/google` ต่อ IP ต่อนาที → 429 problem+json, คำขอที่ 61 ของ refresh → 429, สองโควตาไม่แย่งกัน
11. `docker compose up` ได้ Postgres ที่พร้อมใช้ migration สร้างตารางครบจากฐานข้อมูลว่าง สั่งซ้ำได้โดยไม่พัง
12. หน้าเว็บ: ปุ่ม Google ใช้ได้บนเดสก์ท็อปและความกว้าง 375px แสดงข้อความ "ยังไม่ได้รับอนุญาต" เมื่อได้ 403 และข้อความ+รหัสอ้างอิงเมื่อผิดพลาดอื่น มีข้อความเมื่อโหลดสคริปต์ Google ไม่ได้ ใช้แป้นพิมพ์ได้ คอนทราสต์ผ่าน WCAG AA ข้อความไทย
13. Access token อยู่ในหน่วยความจำเท่านั้น (ไม่อยู่ใน localStorage/sessionStorage) รีเฟรชหน้าแล้วยังอยู่ในระบบ เปิด 2–3 แท็บพร้อมกันได้โดยมีคำขอ Refresh ไม่เกิน 1 ต่อรอบ และไม่ถูกบังคับออกจากระบบผิดพลาด
14. เจอ 401 กลางการใช้งาน: หน้าเว็บ Refresh แล้วลองคำขอเดิมซ้ำ 1 ครั้งไม่เป็นลูป ถ้า Refresh ล้มเหลว → หน้าเข้าสู่ระบบพร้อมข้อความ
15. CI รัน build/format/test/lint ของทั้งสองฝั่งและผ่าน ทำให้ล้มเมื่อ format ผิด Definition of Done ใน `CLAUDE.md` ผ่าน
16. ไม่มีตารางหรือหน้าจอของ Note (ไม่ขยายไป 1b) ไม่เหลือโค้ดสมัคร/ล็อกอินด้วยรหัสผ่าน ล็อกบัญชี โหมดสมัครเปิด/ปิด หรือส่งอีเมล และเอกสารคำแนะนำ (`backend/CLAUDE.md`, `client/CLAUDE.md`, `README.md`) ตรงกับโค้ดจริง (การตรวจว่าถอดเส้นทางรหัสผ่านครบ ดูข้อ 19)
17. **ตรวจด้วยมือหนึ่งครั้งกับ Google จริง** (เทสต์อัตโนมัติใช้ตัวปลอม): บัญชีที่อยู่ในรายชื่อเข้าได้ บัญชีที่ไม่อยู่ในรายชื่อถูกปฏิเสธ ทั้งเดสก์ท็อปและมือถือ
18. ติดต่อ Google เพื่อดึงกุญแจตรวจลายเซ็นไม่ได้ (เทสต์ด้วยตัวตรวจที่ล้มเหลวจากเครือข่าย): ไม่ตอบ 401 และไม่เขียน token ลง log ตอบ 503 (หรือ 500 ทั่วไป) พร้อม `reference` ฝั่งหน้าเว็บแสดง "ตรวจสอบกับ Google ไม่ได้ชั่วคราว ลองอีกครั้ง" และไม่ถือว่าผู้ใช้ออกจากระบบ
19. **ถอดเส้นทาง Email/Password ครบแล้ว (เกณฑ์ปิด 1a):** (ก) `POST /api/auth/register` และ `POST /api/auth/login` ไม่มีอยู่จริง ผู้ที่ล็อกอินแล้วเรียกได้ 404 (มีเทสต์) และไม่ปรากฏใน Swagger (ข) ค้นซอร์สโค้ดและไฟล์ตั้งค่า (`backend`, `client/src`, `appsettings*.json` และไฟล์ตัวอย่าง, `.env.example`) ไม่พบ `RegisterAsync`, `LoginAsync`, `RegisterRequestModel`, `LoginRequestModel`, `CheckPasswordAsync`, `PasswordHasher`, `Registration`, `Lockout`, `emailConfirmed`, `CredentialsForm`, `RegisterPage`, `credentials-validation` และไม่พบ `PasswordHash`, `AspNetUsers`, `AddIdentityCore` ใน `backend` (รวม migration เพราะเลือกทางเลือก B) (ค) ไม่มีช่องกรอกรหัสผ่านในหน้าเว็บใด ไม่มีเส้นทาง `/register` (ง) เทสต์ทั้งหมดผ่านและไม่มีเทสต์ใดใช้ endpoint ที่ถอดแล้ว CI ผ่าน (จ) README และ CLAUDE.md ไม่มีข้อความ "สถานะเปลี่ยนผ่าน" เหลืออยู่ (ฉ) migration ตารางผู้ใช้ใหม่ (ทางเลือก B) ผ่านการอนุมัติของผู้ใช้และสร้างจากฐานข้อมูลว่างได้
