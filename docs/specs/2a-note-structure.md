# to-spec 2a: โครงสร้าง Note (ต้นไม้, ถังขยะ, ค้นหา)

สถานะ: **ร่าง ผู้ใช้ยืนยันคำถาม Q1–Q10 ตามค่าที่เสนอแล้ว (2026-11-11) ส่วนที่เหลือรอผู้ใช้ตรวจ** ยังไม่เขียนโค้ด ยังไม่ commit ทำต่อจาก [1b](1b-note-editor-autosave.md) (ปิดแล้ว 2026-11-11: Note, Editor, Autosave, หน้าชนกัน) spec นี้รวม 3 ฟีเจอร์ที่ใช้กติกาชุดเดียวกัน (ย้ายทั้งกิ่ง, ลบทั้งกิ่ง, กู้เป็น Unplaced, ค้นไม่รวม Trash) ตามที่ผู้ใช้เลือกรวม spec เมื่อ 2026-11-11

ป้ายกำกับ: **[ตัดสินแล้ว]** ผู้ใช้ยืนยัน (อ้างแหล่ง) · **[ร่าง]** ผู้ช่วยเสนอ รอผู้ใช้ตรวจ · **[ยังไม่ได้ตรวจ]** ยังไม่มีหลักฐานทดสอบ · **[คำถาม Qn]** ต้องให้ผู้ใช้ตัดสิน (ค่าที่เสนอเขียนไว้ข้างหลัง)

## Problem Statement

ตอนนี้ผู้ใช้จดและแก้ Note ได้แล้ว (1b) แต่ทุก Note อยู่ในรายการแบนเรียงตามแก้ล่าสุด ไม่มีทางจัดเป็นหมวด ไม่มีทางลบ (ไม่มีวิธีลบ Note เลย) และไม่มีช่องค้นหา เมื่อ Note มากขึ้นจะหาของไม่เจอและไม่มีที่เก็บของที่ไม่ใช้แล้ว Jod คือแอป "จดก่อน จัดทีหลัง" ผู้ใช้ต้องจดได้ทันที แล้วจัดวางทีหลังเป็นต้นไม้ ลบแล้วกู้ได้ และค้นเจอเมื่อต้องการ

## Solution

Note ซ้อนกันเป็นต้นไม้ (Parent/Child) ไม่จำกัดความลึก แถบข้างแสดงต้นไม้ พับ/ขยายได้ มีพื้นที่ "รอจัดวาง" แยกสำหรับ Note ที่ยังไม่มีที่อยู่ Note ที่สร้างใหม่เป็น Unplaced ผู้ใช้เลือกให้เป็นแม่ใหม่ (Root note) หรือย้ายเข้าใต้ Note อื่นด้วยการลากหรือเมนู "ย้ายไปที่…" การย้ายคือย้ายทั้งกิ่งเสมอ ห้ามย้ายเข้าลูกหลานของตัวเอง ลำดับของลูกผู้ใช้จัดเอง หน้า Note มี Breadcrumb ผู้ใช้ลบได้ ("ทั้งกิ่ง" หรือ "เฉพาะ Note นี้") Note ที่ลบไปอยู่ใน Trash เปิดดูได้อย่างเดียว กู้ได้ ลบถาวรได้เมื่อผู้ใช้สั่งเอง ช่องค้นหาค้นชื่อและเนื้อหา (ไม่ค้น Context ไม่รวม Trash) กรองตามกิ่งได้ ผลแสดงชื่อ เส้นทาง และข้อความตัวอย่างพร้อมไฮไลต์

## User Stories

**ต้นไม้และการจัดวาง**
1. ในฐานะผู้ใช้ ฉันต้องการเห็น Note ของฉันเป็นต้นไม้ในแถบข้าง เพื่อเห็นว่าอะไรอยู่ใต้อะไร
2. ในฐานะผู้ใช้ ฉันต้องการพับและขยายกิ่งได้ และให้ระบบจำว่าฉันพับอะไรไว้ในเครื่องนี้ เพื่อไม่ต้องพับใหม่ทุกครั้ง
3. ในฐานะผู้ใช้ ฉันต้องการเห็น Note ที่ยังไม่ได้จัดวางในพื้นที่ "รอจัดวาง" แยกจากต้นไม้ เพื่อรู้ว่าอะไรยังค้างอยู่
4. ในฐานะผู้ใช้ ฉันต้องการให้ Note ใหม่เป็น "รอจัดวาง" เสมอ เพื่อจดได้ทันทีโดยไม่ต้องคิดว่าจะวางที่ไหน
5. ในฐานะผู้ใช้ ฉันต้องการกด "จัดวาง" ที่มุมขวาบนของ Note แล้วเลือก "เป็นแม่ใหม่ (Root note)" หรือ "ปล่อยไว้รอจัดวาง" หรือ "ย้ายไปที่…" เพื่อตัดสินที่อยู่ของ Note
6. ในฐานะผู้ใช้ ฉันต้องการลาก Note ไปวางใต้ Note อื่น หรือวางแทรกระหว่าง Note ในระดับเดียวกัน เพื่อจัดต้นไม้ด้วยมือ
7. ในฐานะผู้ใช้มือถือหรือผู้ใช้แป้นพิมพ์ ฉันต้องการเมนู "ย้ายไปที่…" และปุ่มขึ้น/ลง เพื่อจัดวางได้โดยไม่ต้องลาก
8. ในฐานะผู้ใช้ ฉันต้องการให้การย้ายพาลูกหลานไปด้วยทั้งกิ่งเสมอ เพื่อไม่ทำให้กิ่งแตก
9. ในฐานะผู้ใช้ ฉันต้องการให้ระบบไม่ให้ย้าย Note เข้าตัวเองหรือลูกหลานของตัวเอง พร้อมบอกเหตุผลสั้นๆ
10. ในฐานะผู้ใช้ ฉันต้องการย้าย Note ที่มี Parent ออกมาเป็น Root note ได้
11. ในฐานะผู้ใช้ ฉันต้องการจัดลำดับลูกในระดับเดียวกันเอง และให้ Note ใหม่ต่อท้ายสุด
12. ในฐานะผู้ใช้ ฉันต้องการสร้าง Note ย่อยใต้ Note ที่เปิดอยู่ด้วยปุ่ม "เพิ่ม Note ย่อย" เพื่อสร้างลูกได้ทันที
13. ในฐานะผู้ใช้ ฉันต้องการเห็น Breadcrumb บนหน้า Note และกดไปที่แม่แต่ละชั้นได้
14. ในฐานะผู้ใช้ ฉันต้องการให้ Note ใหม่จากปุ่ม New note ที่ยังว่างและชื่อยังเป็น "Untitled" หายไปเองเมื่อฉันออกจากมัน เพื่อไม่ให้รอจัดวางรกด้วยของว่าง
15. ในฐานะผู้ใช้ ฉันต้องการให้ Note ย่อยที่สร้างด้วยปุ่ม "เพิ่ม Note ย่อย" ไม่ถูกลบเองแม้ยังว่าง เพื่อไม่ทำให้ของที่ฉันตั้งใจสร้างหาย
16. ในฐานะผู้ใช้ ฉันต้องการให้แท็บที่เปิดอยู่เห็นต้นไม้ล่าสุดเมื่อกลับมาที่แท็บ เพื่อไม่ย้ายจากภาพเก่า

**ลบและ Trash**
17. ในฐานะผู้ใช้ ฉันต้องการลบ Note ที่มีลูกโดยเลือกได้ว่า "ลบทั้งกิ่ง" (ค่าเริ่มต้น) หรือ "ลบเฉพาะ Note นี้"
18. ในฐานะผู้ใช้ ฉันต้องการให้ "ลบเฉพาะ Note นี้" ยกลูกขึ้นไปอยู่ที่เดียวกับ Note ที่ถูกลบ เพื่อไม่เสียลูก
19. ในฐานะผู้ใช้ ฉันต้องการเห็นรายการใน Trash และเปิดดูเนื้อหาได้อย่างเดียว (แก้ไม่ได้จนกว่าจะกู้)
20. ในฐานะผู้ใช้ ฉันต้องการกู้ Note ที่เป็นแม่ของกิ่งแล้วได้ทั้งกิ่งกลับมา
21. ในฐานะผู้ใช้ ฉันต้องการกู้ Note ลูกเดี่ยวๆ ขณะแม่ยังอยู่ใน Trash หรือแม่เดิมไม่มีแล้ว ได้เป็น "รอจัดวาง"
22. ในฐานะผู้ใช้ ฉันต้องการกู้ Note ที่ลบแบบ "เฉพาะ Note นี้" กลับมาใต้แม่เดิมต่อท้ายลูก โดยลูกเดิมที่ยกขึ้นไปแล้วไม่ย้ายกลับ
23. ในฐานะผู้ใช้ ฉันต้องการลบถาวรจาก Trash ได้เมื่อฉันสั่งเอง พร้อมกล่องยืนยันที่บอกจำนวน Note ที่จะหาย และให้ระบบไม่ลบถาวรเอง
24. ในฐานะผู้ใช้ ฉันต้องการให้ข้อความที่ยังพิมพ์ค้างในแท็บที่ Note ถูกลบจากอีกแท็บไม่หายเงียบ (เห็นข้อความบอกและคัดลอกเนื้อหาได้)

**ค้นหา**
25. ในฐานะผู้ใช้ ฉันต้องการค้นหาจากชื่อและเนื้อหา (ไม่ค้น Context) เพื่อหา Note ที่จำคำได้
26. ในฐานะผู้ใช้ ฉันต้องการให้พิมพ์ส่วนใดของคำก็เจอ (เช่น "ไทย" เจอใน "ประเทศไทย") ไม่ต้องตัดคำและไม่แก้คำผิด
27. ในฐานะผู้ใช้ ฉันต้องการให้ผลค้นหารวม Note ที่รอจัดวางด้วย แต่ไม่รวม Note ใน Trash
28. ในฐานะผู้ใช้ ฉันต้องการเลือกค้นใน Trash แยก เพื่อหา Note ที่ลบไปแล้ว
29. ในฐานะผู้ใช้ ฉันต้องการกรองผลตาม Note แม่ (รวมลูกหลานทั้งกิ่ง) เพื่อค้นเฉพาะในกิ่งนั้น
30. ในฐานะผู้ใช้ ฉันต้องการให้ Note ที่ชื่อตรงคำค้นมาก่อน ตามด้วย Note ที่เจอเฉพาะในเนื้อหา แต่ละกลุ่มเรียงแก้ล่าสุดก่อน
31. ในฐานะผู้ใช้ ฉันต้องการเห็นชื่อ เส้นทางในต้นไม้ และข้อความตัวอย่าง (~100 ตัวอักษร) พร้อมไฮไลต์คำที่ค้น
32. ในฐานะผู้ใช้ ฉันต้องการผลทีละ 50 รายการและปุ่ม "โหลดเพิ่ม"

**ข้ามหมวด**
33. ในฐานะผู้ใช้ ฉันต้องการเห็นเฉพาะ Note ของฉัน และเปิดหรือย้ายหรือลบ Note ของคนอื่นไม่ได้แม้รู้รหัส (ตอบ 404 เหมือน 1b)
34. ในฐานะผู้ใช้ ฉันต้องการให้ Note ที่ฉันเขียนไว้ใน 1b ทุกอันยังอยู่ครบ และเป็น "รอจัดวาง" หลังอัปเกรด
35. ในฐานะผู้ใช้มือถือ ฉันต้องการใช้ต้นไม้ ค้นหา ย้าย ลบ และ Trash ได้ครบจากลิ้นชัก
36. ในฐานะผู้ดูแลระบบ ฉันต้องการให้ชื่อและเนื้อหา Note ที่ค้นหาไม่ปรากฏใน log และ error

## Implementation Decisions

**ตัดสินแล้ว (จาก ticket ที่ปิดแล้ว)**

- **[ตัดสินแล้ว, ticket 001, 003]** Unplaced note = Note ไม่มี Parent ที่ไม่ใช่ Root note ส่วน Root note = ไม่มี Parent โดยผู้ใช้ตั้งใจ (สร้างให้เป็นระดับบนสุดหรือย้ายออกมาเอง)
- **[ตัดสินแล้ว, ticket 003]** ย้ายทั้งกิ่งเสมอ ห้ามย้ายเข้าตัวเอง/ลูกหลาน ลำดับลูกผู้ใช้จัดเอง (ลากสลับ) Note ใหม่ต่อท้ายสุด ความลึกไม่จำกัด
- **[ตัดสินแล้ว, ticket 002]** Note ใหม่จาก New note ปิดโดยไม่เลือกที่วาง = Unplaced Note ว่างที่ Title ยังเป็นค่าเริ่มต้นถูกลบถาวร ไม่ผ่าน Trash เฉพาะ Note ที่สร้างจากปุ่ม New note
- **[ตัดสินแล้ว, ticket 004]** ลบ "ทั้งกิ่ง" (ค่าเริ่มต้น) หรือ "เฉพาะ Note นี้"; กู้แม่ของกิ่ง = กู้ทั้งกิ่ง; กู้ลูกเดี่ยวหรือแม่เดิมไม่มี = Unplaced; กู้ Note ที่ลบเฉพาะตัว = ใต้แม่เดิมต่อท้าย ลูกเดิมไม่ย้ายกลับ; ลบถาวรผู้ใช้สั่งเอง พร้อมยืนยัน ไม่มีกวาดอัตโนมัติ; Note ใน Trash เปิดดูอย่างเดียว
- **[ตัดสินแล้ว, ticket 010]** ค้นชื่อ+เนื้อหา ไม่ค้น Context รวม Unplaced ไม่รวม Trash (ค้นใน Trash แยก) Filter ตาม Parent รวมทั้งกิ่ง ค้นแบบข้อความย่อย ไม่ตัดคำไทย ไม่แก้คำผิด ผลเรียงชื่อตรงก่อน แล้วแก้ล่าสุด 50 รายการต่อหน้า (ค่าเริ่มต้นใน product-spec หัวข้อ 6)
- **[ตัดสินแล้ว, ticket 017]** Layout C: Writing canvas โล่ง แถบข้าง ~300 px ซ่อนได้ ปุ่ม "จัดวาง" เล็กที่มุมขวาบน
- **[ตัดสินแล้ว, product-spec หัวข้อ 15]** ขนาดเป้าหมาย: ไม่เกินหลักหมื่น Note ต่อบัญชี ต้องออนไลน์ ไม่มีโหมดออฟไลน์
- **[ตัดสินแล้ว, 1b]** โครง API ใต้ `/api` ต้องล็อกอิน, Note ของคนอื่นหรือไม่มี = 404 เหมือนกัน, `baseVersion` ตรวจชนกันเฉพาะเนื้อหา, ข้อความเนื้อหาไม่ปรากฏใน log

**ร่าง (ผู้ช่วยเสนอ รอผู้ใช้ตรวจ)**

- **ข้อมูล:** เพิ่มคอลัมน์ในตาราง `Notes` เดิม: `Placement` (`Unplaced` | `Root` | `Child`), `ParentId` (null เมื่อไม่ใช่ Child, อ้างตารางเดียวกัน), `Position` (จำนวนเต็ม ลำดับในกลุ่มพี่น้อง), `DeletedAt` (null = ไม่ถูกลบ), `TrashBatchId` (รหัสการลบครั้งเดียวกัน ใช้รู้ว่า "ทั้งกิ่ง" เดียวกัน), `OriginalPlacement`/`OriginalParentId` (ที่อยู่ก่อนลบ ใช้กู้) และ `SearchText` (ข้อความล้วนของเนื้อหา ดูหัวข้อค้นหา) Note ของ 1b ทุกอันได้ `Placement = Unplaced` ตอน migrate
- **การเปลี่ยนโครงสร้างไม่เพิ่ม `Version` และไม่เปลี่ยน `UpdatedAt`:** เลขเวอร์ชันมีไว้ตรวจชนกันของเนื้อหา (ชื่อ Context เนื้อหา) ถ้าการย้ายเพิ่มเลข แท็บที่เปิดแก้อยู่จะชนกันโดยไม่จำเป็น การบันทึกเนื้อหาเดิม (`ExecuteUpdate` เงื่อนไขเดียว) ไม่แตะคอลัมน์โครงสร้าง จึงไม่ทับการย้าย รายการ "แก้ล่าสุด" จึงหมายถึงแก้เนื้อหา
- **API (ใต้ `/api/notes` ต้องล็อกอิน):**
  - รายการ Note (แบนทั้งหมดที่ไม่อยู่ใน Trash): `id`, `title`, `updatedAt`, `placement`, `parentId`, `position` หน้าเว็บประกอบต้นไม้เอง ไม่ส่งเนื้อหา (หลักหมื่นรายการ ราว 1 MB ยังรับได้ ไม่แบ่งหน้า) [คำถาม Q8]
  - สร้าง Note: รับ `parentId` ได้ (ถ้ามี = Child ต่อท้ายลูกของแม่นั้น ไม่มี = Unplaced)
  - ย้าย/จัดวาง: ส่งปลายทางเป็น `placement` กับ `parentId` และ `beforeId` (วางก่อน Note ไหน ไม่ส่ง = ต่อท้าย) เซิร์ฟเวอร์ตรวจวงวน (ปลายทางต้องไม่ใช่ตัวเองหรือลูกหลาน) และคำนวณ `Position` ใหม่ของกลุ่มพี่น้องในธุรกรรมเดียว ใช้ `beforeId` ไม่ใช้เลขตำแหน่ง เพราะหน้าจอที่ค้างอยู่อาจเป็นภาพเก่า
  - ลบ: `scope` = `branch` | `single` ตอบจำนวน Note ที่ถูกลบ; ลบถาวรแบบ "Note ว่างจาก New note" เป็นคำขอแยกที่เซิร์ฟเวอร์ตรวจเองว่ายังว่างจริง ไม่เชื่อหน้าเว็บ
  - Trash: รายการ (เฉพาะหัวกิ่งของแต่ละการลบ), กู้, ลบถาวร
  - ค้นหา: `q`, `parentId` (ไม่ส่ง = ทั้งหมด), `inTrash`, หน้าถัดไป ผลแต่ละรายการมี `id`, `title`, `path` (ชื่อแม่ทุกชั้น), `snippet`
  - Note ที่ถูกลบ: อ่านได้ (มี `deletedAt`) บันทึกไม่ได้ ตอบ 404 เหมือน Note ที่ไม่มี เพื่อใช้การแสดงผลและปุ่มคัดลอกที่ Autosave มีอยู่แล้วสำหรับความผิดพลาดแบบลองใหม่ไม่ช่วย (เรื่องที่ 24)
- **ลบ "เฉพาะ Note นี้":** ลูกตรงของมันรับที่อยู่ของมัน (Child ใต้แม่ของมัน, Root → Root, Unplaced → Unplaced) ต่อท้ายหรือแทรกที่ตำแหน่งเดิมของมัน [คำถาม Q2] ตัวมันได้ `TrashBatchId` ใหม่ มีแค่ตัวเดียว
- **ลบ "ทั้งกิ่ง":** Note และลูกหลานทั้งหมดได้ `DeletedAt` และ `TrashBatchId` เดียวกัน
- **กู้:** กู้หัวกิ่ง = กู้ทุก Note ที่มี `TrashBatchId` เดียวกัน ไปที่ `OriginalParentId`/`OriginalPlacement` ต่อท้าย ถ้าที่เดิมใช้ไม่ได้ (แม่ถูกลบ/ลบถาวร) = Unplaced กู้ Note ในกิ่งที่ไม่ใช่หัวกิ่ง = Note นั้นกับลูกหลานในการลบเดียวกันของมัน ออกมาเป็น Unplaced [คำถาม Q3]
- **ลบถาวร:** ลบ Note ที่เลือกกับลูกหลานที่ยังอยู่ใน Trash การลบเดียวกันของมัน (ไม่ให้เหลือลูกกำพร้าใน Trash) กล่องยืนยันบอกจำนวน [คำถาม Q4]
- **ลบ Note ว่างอัตโนมัติ:** หน้าเว็บเรียกเมื่อผู้ใช้ออกจาก Note ที่สร้างจากปุ่ม New note ในแท็บนี้ และ Note ยังว่าง/ชื่อเริ่มต้น เซิร์ฟเวอร์ตรวจซ้ำว่า Note นั้นว่างจริง ไม่มีลูก และยังเป็นเวอร์ชันที่ผู้เรียกเห็น ก่อนลบถาวร ถ้าปิดแท็บเลย Note ว่างค้างเป็น Unplaced ไม่มีกวาด [คำถาม Q6]
- **ค้นหา:** เพิ่ม `SearchText` (เนื้อหาล้วนที่ดึงจากเอกสาร Block ตอนบันทึก ในธุรกรรมเดียวกับการบันทึก) และดัชนี trigram (`pg_trgm`) ของ `Title` และ `SearchText` ให้ `ILIKE '%คำ%'` เร็วและทำงานกับภาษาไทยโดยไม่ต้องตัดคำ ต้องเปิดส่วนขยาย `pg_trgm` ในฐานข้อมูล (มากับ PostgreSQL 16) ถ้าเลือกวิธีนี้ควรบันทึก ADR [คำถาม Q7] Note เก่าของ 1b ต้องเติม `SearchText` ตอน migrate ก้าวเดียว
- **`snippet`:** ตัดจาก `SearchText` ราว 100 ตัวอักษรรอบคำที่เจอครั้งแรก ไฮไลต์ทำฝั่งหน้าเว็บจากคำค้น
- **`path`:** เซิร์ฟเวอร์ส่งชื่อแม่ทุกชั้นของแต่ละผล (ผลของ Trash ส่งเส้นทางเดิมก่อนลบ) ด้วยคำสั่งเดียวแบบเรียกซ้ำ ไม่ให้หน้าเว็บต้องรู้ต้นไม้ทั้งหมด
- **ความลึก:** ผลิตภัณฑ์ไม่จำกัด แต่เซิร์ฟเวอร์ใช้การไล่ขึ้นและลงแบบวนซ้ำที่มีเพดานเทคนิค (เสนอ 200 ชั้น) เพื่อไม่ให้ข้อมูลผิดปกติทำให้ค้าง [คำถาม Q9]
- **ลากและวาง:** ใช้ HTML5 drag and drop ของเบราว์เซอร์ ไม่เพิ่ม dependency และทำทางสำรองด้วยเมนู "ย้ายไปที่…" กับปุ่มขึ้น/ลง (แป้นพิมพ์และมือถือ) [คำถาม Q5]
- **หน้าเว็บ:** แถบข้างแสดง "รอจัดวาง", ต้นไม้ Root note, Trash และช่องค้นหา สถานะพับ/ขยายเก็บใน `localStorage` ต่อเครื่อง (ตัวช่วยความสะดวกเท่านั้น ใช้ได้โดยไม่มี) Breadcrumb อยู่เหนือชื่อ Note หน้า Note ที่อยู่ใน Trash เปิดแบบอ่านอย่างเดียวพร้อมแถบ "อยู่ใน Trash" กับปุ่มกู้ (ใช้ตัว Editor แบบอ่านอย่างเดียวที่ 1b สร้างไว้) ดึงต้นไม้ล่าสุดเมื่อกลับมาที่แท็บ ตามหลักเดียวกับ Autosave
- **ปุ่ม New note:** อยู่ในแถบข้างต่อไปเหมือนตอนนี้ (ข้อเบี่ยง D8 ของ 1b จาก product-spec ที่ให้อยู่หน้าแรกเท่านั้น) [คำถาม Q1]
- **ปุ่ม "จัดวาง":** มี 3 ทาง: เป็นแม่ใหม่ (Root note), ปล่อยไว้รอจัดวาง, ย้ายไปที่… ทางที่ 4 "ให้ AI จัดให้" มาใน spec D ยังไม่แสดง
- **ชื่อ/ชนิดใหม่ที่เสนอ (ตามกฎ `backend/CLAUDE.md` และ `client/CLAUDE.md` ต้องขอผู้ใช้ยืนยันก่อนตั้ง):** `Placement` (enum), `TrashBatchId`, `NoteTreeItemViewModel`, `NoteSearchResultViewModel`, `INoteStructureService`/`NoteStructureService` (ย้าย ลบ กู้ — แยกจาก `NoteService` เดิมที่เป็นเรื่องเนื้อหา), `NoteSearchService`, ฝั่งหน้าเว็บ `utils/tree/` (ประกอบต้นไม้, หาลูกหลาน, ตรวจวงวน, คำนวณปลายทางการวาง), `NoteTree`, `NoteTreeNode`, `TrashPage`, `NoteSearchBox`, `MoveNoteDialog`, `Breadcrumb`

## คำถาม Q1–Q10 (ผู้ใช้ตอบ "ได้เลย" ต่อค่าที่เสนอทั้งหมด เมื่อ 2026-11-11: ถือเป็น [ตัดสินแล้ว] ตามค่าที่เสนอ)

- **Q1 ปุ่ม New note:** product-spec ให้อยู่ "หน้าแรกเท่านั้น" แต่ตอนนี้อยู่ในแถบข้าง (D8 ของ 1b) เสนอ: คงไว้ในแถบข้าง เพราะต้นไม้ทำให้ "หน้าแรก" ไม่ชัด
- **Q2 ลบ "เฉพาะ Note นี้" ของ Note ที่เป็น Unplaced และมีลูก:** ลูกเป็นอะไร เสนอ: ลูกเป็น Unplaced (รับที่อยู่ของแม่ที่ถูกลบ) และถ้า Unplaced Note มีลูกได้ตามที่ product-spec ให้ `/Note` สร้างลูกใต้ Note ใดก็ได้ ให้ Unplaced มีลูกได้
- **Q3 กู้ Note ที่ไม่ใช่หัวกิ่ง:** พาลูกหลานในการลบเดียวกันมาด้วยไหม เสนอ: พามา (สอดคล้อง "ย้ายทั้งกิ่งเสมอ")
- **Q4 ลบถาวร Note ที่มีลูกหลานใน Trash:** ลบกับลูกหลานทั้งหมดของการลบเดียวกัน พร้อมบอกจำนวนในกล่องยืนยัน เสนอ: ตามนี้
- **Q5 ลากและวาง:** ใช้ของเบราว์เซอร์ (ไม่มี dependency) หรือเพิ่มไลบรารี (ต้องขออนุมัติตามกฎ `client/CLAUDE.md`) เสนอ: ของเบราว์เซอร์ก่อน
- **Q6 Note ว่างที่ค้างเมื่อปิดแท็บ:** ลบเมื่อออกจาก Note เท่านั้น แท็บที่ปิดตรงๆ ปล่อยเป็น Unplaced ว่าง (ไม่มีงานกวาดเบื้องหลัง) หรืออยากให้กวาด เสนอ: ไม่กวาด
- **Q7 วิธีค้นหา:** `SearchText` + `pg_trgm` + `ILIKE` ใน PostgreSQL (ไม่ต้องเพิ่มระบบค้นหาแยก) เสนอ: ตามนี้ และเขียน ADR
- **Q8 รายการแบนไม่แบ่งหน้า:** เหมาะกับเป้าหลักหมื่น Note ต่อบัญชี เสนอ: ไม่แบ่งหน้าใน 2a ทบทวนเมื่อใกล้เป้า
- **Q9 เพดานความลึกของต้นไม้ที่เซิร์ฟเวอร์:** เสนอ 200 ชั้น (ผลิตภัณฑ์ไม่จำกัด เพดานนี้กันข้อมูลผิดปกติ)
- **Q10 ลำดับ Unplaced:** เรียงแก้ล่าสุดก่อน (เหมือนรายการตอนนี้) แทนลำดับที่ผู้ใช้จัดเอง เสนอ: ตามนี้
