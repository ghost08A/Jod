## Resolution

ตัดสินแล้ว (2026-10-19) ทีละข้อ:

- ฐานข้อมูล: PostgreSQL (ADR 0004)
- โครง Tree: แม่-ลูกตรงๆ (Parent + ตัวเลขลำดับในหมู่พี่น้อง) ไล่ด้วย recursive query Alias แยกตาราง (ADR 0004)
- เนื้อหา Block: 1 Note = เอกสาร JSON ก้อนเดียว + ตารางไฟล์อ้างอิง (ADR 0005)
- Undo: เก็บฉบับล่าสุดฉบับเดียวต่อ Note อายุ 30 วันแล้วลบเอง แก้เพิ่มหลัง AI จัดแล้ว Undo = แจ้งเตือน (ADR 0005)
- ตรวจบันทึกชนกัน: เลขเวอร์ชันต่อ Note ไม่มีข่าวสดข้ามแท็บ (ADR 0005)
- ล็อกอิน (ตัดสินใหม่ 2026-10-20 แทนฉบับ email + รหัสผ่านเดิม): Google Sign-In อย่างเดียว Backend ตรวจ Google ID token ใช้ Google `sub` ระบุตัวตน แล้ว Jod ออก Access token 15 นาที/Refresh token 30 วัน หมุนทุกครั้ง ประสานแท็บฝั่ง Client กลุ่มปิดด้วยรายชื่ออีเมลที่อนุญาต ไม่มีรหัสผ่าน ลิงก์ยืนยัน/รีเซ็ต หรือการส่งอีเมล (ADR 0006)
- ที่เก็บไฟล์: SeaweedFS 4.48 เป็นตัวเลือกสำหรับ v1 และเป็นฐานพัฒนาจาก PoC (branch `prototype/seaweedfs-s3`, commit `c6f9eee`, โค้ดทิ้งไม่เข้า dev) ตั้งค่าความปลอดภัยตาม ADR 0008 เปิดไฟล์ผ่าน Backend ใน v1 (ADR 0001) **ยังมีเงื่อนไขก่อน Production** ที่ยังไม่ผ่านตามที่ระบุใน ADR 0001 และ 0008 (ขีดจำกัดไฟล์ OQ-3 ตัดสินแล้ว ดูบรรทัดด้านล่าง) คำถามค้างเรื่องผู้รับ Share Link ดาวน์โหลดไฟล์: OQ-7
- การเรียก AI (ตัดสินแล้ว 2026-10-19): ฝั่ง Service เรียก Gemini ผ่าน Interface แคบ 2 การทำงาน (เสนอที่วาง, เสนอชุดการเปลี่ยนแปลง) ด้วยไลบรารีทางการ `Google.GenAI` ไม่ใช้ streaming อ่านชื่อโมเดลจากค่าตั้งค่า และไม่ให้ชนิดข้อมูลของ Google หลุดออกนอกชั้น Service ชื่อ Interface ให้ผู้ใช้ยืนยันก่อนตั้ง ถ้าไลบรารีส่วน C# ใช้ไม่ได้ตามเอกสาร เปลี่ยนไปเรียก HTTP เองได้หลัง Interface เดิม
- ข้อผิดพลาดของ AI: ผู้ใช้เห็นข้อความแบบเดียว ("AI ใช้ไม่ได้ตอนนี้ ลองใหม่ได้") พร้อมรหัสอ้างอิง แต่ log เก็บข้อผิดพลาดจริงที่แยกชนิดได้: รหัสอ้างอิง, เวลา, ชนิดงาน, HTTP status, สถานะของ Google, `blockReason`/`finishReason`, ตัวระบุโควตาถ้ามี, จำนวนครั้งที่ลองใหม่, เวลาที่ใช้, ชนิดและตำแหน่งของ Block ที่ไม่ผ่านการตรวจ Protected Block ไม่เก็บเนื้อหา Note/Context, ข้อความที่ส่งให้หรือได้จาก AI, คีย์ และข้อความอิสระจาก Google
- การลองใหม่ของ AI: สูงสุด 2 ครั้งเฉพาะ 429/408/5xx/หมดเวลา เว้นราว 1 วินาทีแล้วราว 3 วินาที (สุ่มเล็กน้อย) ไม่ลองใหม่เมื่อเป็น 400/402/403 หรือผลลัพธ์ใช้ไม่ได้ หมดเวลาต่อครั้ง 30 วินาที ค่าทั้งหมดเป็นค่าตั้งค่า ยังไม่ได้ทดสอบกับ Gemini จริง
- โควตา AI: ไม่จำกัดการใช้ในแอปใน v1 (โควตาตัวฟรีนับรวมทั้งโปรเจกต์) ใช้ log ประเมิน และทบทวนเมื่อพบ 429 เกิดซ้ำจนผู้ใช้ร้องเรียนหรือผู้ใช้เห็นในหน้า AI Studio ว่าใกล้เต็ม
- ความลับ: ตอนพัฒนาเก็บคีย์จริงในไฟล์ `appsettings.Development.json` ซึ่ง gitignore และไม่ commit (แม่แบบ `appsettings.Development.example.json`) ห้ามใส่ความลับใน `appsettings.json` หรือไฟล์ตั้งค่าอื่นที่ยังถูกติดตามใน git ตอน Production ใช้ environment variables หรือระบบจัดการความลับ ผู้ใช้เป็นคนใส่คีย์จริงเอง ต้องใส่ `appsettings.Development.json` ใน `.dockerignore` ตอนทำ Dockerfile
- ค้นหา (ตัดสินแล้ว 2026-10-19): ค้นแบบข้อความย่อยด้วย `ILIKE` ทั้ง Title และคอลัมน์ข้อความธรรมดาที่ดึงจากเนื้อหา Block (อัปเดตตอนบันทึก) บน PostgreSQL (ADR 0004) ไม่ใส่ดัชนีใน v1 ทดสอบกับข้อมูลสมมติ 50,000 Note (เจ้าของละ ~9,500 Note ใช้งานอยู่ เฉลี่ย ~1,800 ตัวอักษร) ค้นได้ ~0.25–0.5 วินาทีต่อครั้ง ส่วนดัชนี `pg_trgm` ทำให้คำเฉพาะเจาะจงเร็วขึ้นเหลือ 1–2 มิลลิวินาที แต่ไม่ช่วยคำที่ตรงเกือบทุก Note หรือสั้นกว่า 3 ตัวอักษร และใช้พื้นที่เพิ่มราวเท่าตาราง เติมดัชนีเมื่อค้นช้ากว่าราว 1 วินาทีหรือรู้สึกว่าช้า PostgreSQL ตัดคำไทยสำหรับค้นแบบเต็มข้อความไม่ได้ (ทดสอบแล้ว) ยังไม่ได้ทดสอบ: รูปสระ "ำ" สองแบบ (ต้อง normalize NFKC หรือไม่), การกรองตาม Parent รวมลูกหลานร่วมกับการค้น, ข้อมูลจริง ลำดับและการแสดงผลตามที่ระบุใน product-spec หัวข้อ 6
- ลิงก์แชร์ (ตัดสินแล้ว 2026-10-19): คำนวณเซต Note ที่ลิงก์เปิดได้ตอนมีคำขอด้วย recursive query (ลูกและการ์ดตามกฎ ticket 009) ตรวจ "อยู่ใต้ราก" ก่อนด้วยการไล่ขึ้นหาแม่ (~0.15 มิลลิวินาที) ถ้าไม่ใช่ จึงคำนวณเซตรวมการ์ด (ทดสอบข้อมูลสมมติ 10,000 Note: ~2–100 มิลลิวินาที) ต้องเพิ่มตารางการ์ดทิศไปข้างหน้า (Note→ปลายทาง) อัปเดตตอนบันทึก (แก้ ADR 0005) ไม่เก็บรายการล่วงหน้า ไม่แคชใน v1 โทเคนสุ่ม 256 บิต เก็บตัวจริงในฐานข้อมูล หลายลิงก์ต่อ Note จำกัด email ได้ ≤20 ต่อลิงก์ ผู้รับใช้ endpoint แยกสำหรับดูอย่างเดียว พร้อมชนิดข้อมูลตอบกลับของตัวเอง (ไม่มี Context ข้อเสนอ AI สถานะ Trash) วันหมดอายุสิ้นวันเวลาไทย ลิงก์ใช้ไม่ได้แสดงหน้าเดียวกันทุกสาเหตุ ไม่เก็บสถิติการเปิด ไม่จำกัดอัตราเฉพาะลิงก์ ยังไม่ได้ทดสอบ: การตาม Alias ของ Note ที่ถูก Merge, การกรอง Trash ร่วมกัน, ข้อมูลจริง, คำขอพร้อมกัน ค้างตัดสินใจ: OQ-7, OQ-8, OQ-9 รายละเอียดข้อกำหนดและเงื่อนไขก่อนลงมือทำใน ADR 0009
- diff หน้าตรวจผล AI (ตัดสินแล้ว 2026-10-19): เทียบเป็นรายคำในเบราว์เซอร์ด้วย `Intl.Segmenter('th')` เทียบด้วยรูปที่ผ่าน NFKC แต่แสดงข้อความเดิมของผู้ใช้ ถอยไปเทียบระดับตัวอักษรเมื่อเบราว์เซอร์ไม่มีตัวตัดคำ ใช้เฉพาะรายการชนิด "แก้ไข" ภายใน Block ทดสอบเฉพาะบน Node (V8) กับข้อความตัวอย่าง 5 คู่ ยังไม่ได้ทดสอบ Firefox, Safari/iOS และย่อหน้ายาวที่ AI เขียนใหม่ทั้งหมด
- Autosave (ตัดสินแล้ว 2026-10-19): หน่วง 1 วินาที เพดานรอ 10 วินาที บันทึกเมื่อ `visibilitychange` เป็นซ่อนด้วย `fetch keepalive` พร้อม Authorization (ไม่ใช้ `sendBeacon`) กล่องยืนยันตอนปิดเฉพาะเมื่อมีการแก้ที่ยังไม่บันทึก บันทึกครั้งละหนึ่งคำขอ ลองใหม่เอง 3 ครั้ง (2, 5, 10 วินาที) เฉพาะความผิดพลาดชั่วคราว (เครือข่าย หมดเวลา 5xx) ไม่ลองซ้ำกับ 4xx อื่นที่ซ้ำแล้วไม่ช่วย (เช่น ขนาดเกินหรือไม่มีสิทธิ์) ถ้าครบแล้วยังไม่สำเร็จแสดง "บันทึกไม่สำเร็จ" พร้อมปุ่มลองใหม่ และเก็บข้อความที่ยังไม่บันทึกไว้ในจอ ห้ามแสดงว่าบันทึกแล้ว สถานะ "บันทึกแล้ว" แสดงได้เมื่อเซิร์ฟเวอร์ตอบสำเร็จสำหรับฉบับล่าสุดของเนื้อหาเท่านั้น (การแก้ระหว่างบันทึกถือว่ายังไม่บันทึก) 401 ต่ออายุ token แล้วลองใหม่ 1 ครั้ง 409 ไปหน้าบันทึกชนกัน ยังไม่ได้ทดสอบกับเบราว์เซอร์จริง เป็นเกณฑ์ตรวจรับของ Editor จริง (สองแท็บ ปิดแท็บกลางพิมพ์ สลับแอปบนมือถือ ตัดเน็ตแล้วต่อใหม่)
- ขีดจำกัดไฟล์ OQ-3 (ตัดสินแล้ว 2026-10-19): รูปภาพ JPEG/PNG/WebP/GIF ไม่เกิน 15 MB (ไม่รับ SVG, HEIC) ไฟล์ทั่วไปรับทุกชนิดไม่เกิน 25 MB ไฟล์ทั่วไปเปิดเป็นดาวน์โหลดเสมอ รูปภาพเปิดในหน้าได้เมื่อตรวจชนิดจากเนื้อไฟล์จริงแล้ว ไม่ตรวจไวรัส ไม่มีโควตาต่อบัญชีใน v1 ยังไม่ได้ทดสอบอัปโหลดจริงผ่าน Backend
- ตรวจ ADR (2026-10-19): ADR 0004–0006, 0008, 0009 ครอบคลุมเรื่องที่เข้าเงื่อนไข เรื่องอื่นย้อนกลับง่ายหรือมี ADR ครอบอยู่แล้ว ไม่มีเรื่องที่ต้องเขียนเพิ่ม

ปิด ticket 2026-10-19 (ผู้ใช้ยืนยันตัวเลือก A): ทุกหัวข้อเป็น Decided หรือ Deferred พร้อมเหตุผล ส่วน Deferred คือเงื่อนไขก่อน Production ซึ่งติดตามที่ ADR 0001, 0008, 0009 และคำถามค้างใน `docs/open-questions.md` ยังไม่เปิด ticket ใหม่ ให้พิจารณาเปิดหนึ่งใบสำหรับความพร้อมก่อน Production ตอนเริ่มลงมือ ช่องว่างที่พบ: เงื่อนไขเรื่องการสำรอง PostgreSQL เพิ่มใน ADR 0004 แล้ว ส่วนตัวเลขงานเก็บกวาดไฟล์ (ช่วงผ่อนผัน ความถี่ อายุ multipart ค้าง) ยังรอตัดสินตอนลงมือทำ
