## Question

เมื่อผู้ใช้ต้องตรวจผลที่ AI จัดโครงสร้าง Note และจัดการกรณีแก้ Note เดียวกันจากสองแท็บ ควรแสดงความแตกต่างอย่างไรให้ตรวจสอบได้จริง โดยยังอ่านเนื้อหาได้ง่ายและไม่ทำให้ผู้ใช้ยืนยันผลที่ผิดพลาด?

## Scope

Prototype นี้ทดลอง UX เท่านั้น ไม่ใช่ production implementation และไม่ตัดสิน Product Behavior ใหม่

### Scenario A — AI จัดโครงสร้าง

- เปรียบเทียบฉบับเดิมกับฉบับที่ AI เสนอ
- แสดงข้อความที่เพิ่ม แก้ หรือนำออก
- แสดง Reference Card, Link, Code Block และไฟล์ที่ต้องคงอยู่
- แสดงกรณีระบบตรวจพบว่า AI เปลี่ยน Block ที่ห้ามแตะต้อง และปฏิเสธผลลัพธ์
- ให้ผู้ใช้เลือกผลลัพธ์แยกเป็นราย Block ได้: ใช้ Block ที่ AI เสนอ หรือคง Block เดิม
- แสดงผลลัพธ์รวมที่ได้จากการเลือกแต่ละ Block ก่อนยืนยันการนำไปใช้

### Scenario B — บันทึกชนกัน

- แสดงความแตกต่างระหว่างฉบับในแท็บนี้กับอีกแท็บ
- ทดลองตัวเลือกที่ Product Design กำหนดไว้: ใช้ฉบับนี้ / ใช้ฉบับอีกแท็บ / เก็บทั้งสอง
- เมื่อเลือกเก็บทั้งสอง ฉบับอีกแท็บกลายเป็น Unplaced note ตามกฎที่ยืนยันแล้ว
- อย่าสมมติว่าการเลือกฉบับเป็นราย Block ใช้ได้กับ conflict scenario จนกว่าจะทดลองและตัดสินใจ

## Variants

- A — Side-by-side: แสดงสองฉบับเทียบกัน
- B — Inline diff: แสดงความแตกต่างในเนื้อหาเดียว
- C — Peek toggle: คงหน้าตา Note ปกติ แล้วสลับดูแต่ละฉบับพร้อมเครื่องหมายบอกจุดเปลี่ยน

ผู้ใช้ทดลองแล้วชอบ **Variant A — Side-by-side** เพราะอ่านง่ายและเห็นสิ่งที่เปลี่ยนได้ชัดเจน

ข้อเสนอแนะที่ต้องนำไปทดลองเพิ่ม:
- ใน Scenario A ให้เลือกได้เป็นราย Block ว่าจะใช้เวอร์ชันที่ AI เสนอหรือเวอร์ชันเดิม
- ต้องแสดงตัวอย่างผลลัพธ์รวมหลังเลือกแต่ละ Block เพื่อให้ผู้ใช้ตรวจสอบก่อนยืนยัน
- ยังไม่ปิด Ticket จนกว่าจะได้ทดลอง interaction ราย Block และตรวจกรณี AI ตรวจไม่ผ่าน
- ยังไม่ได้สรุปว่า Variant A เหมาะที่สุดสำหรับ Scenario B (บันทึกชนกัน)

## สิ่งที่ต้องสังเกต

- ผู้ใช้มองเห็นได้ทันทีหรือไม่ว่าอะไรเพิ่ม แก้ และหายไป
- อ่าน Note ยาวได้หรือไม่ โดยไม่เสียบริบทของเนื้อหา
- ผู้ใช้ตรวจ Block ที่ห้ามแก้ได้ง่ายหรือไม่
- ผู้ใช้เข้าใจผลของปุ่มแต่ละปุ่มก่อนยืนยันหรือไม่
- การเลือกเวอร์ชันต่อ Block ทำได้ง่ายและไม่ทำให้เกิดการเปลี่ยนแปลงโดยไม่ตั้งใจหรือไม่
- เมื่อระบบตรวจไม่ผ่าน ผู้ใช้เข้าใจหรือไม่ว่าฉบับเดิมยังปลอดภัย
- การเปลี่ยน Variant ช่วยตัดสินใจจริงหรือเพียงเปลี่ยนหน้าตา

## Resolution

ยังเปิดอยู่ — ผลเบื้องต้นสำหรับ Scenario A คือ Variant A (Side-by-side) พร้อมความต้องการเลือกเวอร์ชันแยกเป็นราย Block; ต้องทำ Prototype เพิ่มก่อนยืนยันรายละเอียด interaction และก่อนปิด Ticket.
