## Question

เมนู `/` ควรหน้าตาและความรู้สึกอย่างไรบน canvas เขียนโล่ง (017) ทั้งบนคอมพิวเตอร์และมือถือ (019): เมนูแสดงเมื่อพิมพ์ `/` แล้วกรองตามที่พิมพ์ จัดกลุ่มตามหมวดใน ticket 020, เลือกด้วยคีย์บอร์ดและการแตะ

สิ่งที่ต้องทดลอง:
- ค้นหา Note ใน `/reference` และวิธีเลือก Note ที่ต้องการ (เช่น ชื่อซ้ำ แสดง Breadcrumb กำกับ) ต้องไม่เปลี่ยน Parent ของ Note ที่อ้างอิง
- `/note` ควรสร้าง Note ทันที หรือเปิดขั้นตอนให้ตั้งชื่อก่อน **ทดลองเป็นข้อเสนอเท่านั้น ห้ามเปลี่ยนกฎเดิม (สร้างทันที ไม่ถูกลบเอง จาก ticket 002) โดยไม่บันทึกข้อเสนอให้ผู้ใช้ตัดสิน**
- แยก `/note` กับ `/reference` ให้ผู้ใช้เห็นความต่างชัดในเมนู
- เมนู `/` บนจอมือถือและแป้นพิมพ์มือถือ

กฎที่ห้ามเปลี่ยน: ticket 001, 002, 020 และทิศทาง UX ของ 017

## Resolution

ผู้ใช้ทดลอง prototype แล้วเลือก **Variant A** (กฎเดิมไม่เปลี่ยน)

- เมนู `/`: รายการลอยใต้บรรทัดที่พิมพ์ แบ่งหัวข้อตาม 3 หมวด (ข้อความและโครงสร้าง / Note และลิงก์ / เนื้อหาพิเศษ) มีไอคอนและคำอธิบายสั้นใต้แต่ละคำสั่ง
- เรียกเมนูด้วยการพิมพ์ `/` ที่ต้นบรรทัดหรือหลังช่องว่าง พิมพ์ต่อเพื่อกรอง (ตามชื่อคำสั่ง ชื่อไทย และคำค้นอื่น) เลือกด้วย ↑ ↓ Enter/Tab หรือแตะ Esc ปิด
- `/note` **สร้างทันที** (กฎเดิมจาก ticket 002 ไม่เปลี่ยน ข้อเสนอ "ตั้งชื่อก่อนสร้าง" ที่ทดลองใน Variant B ไม่ถูกเลือก) ได้ Note ลูกชื่อ Untitled ใต้ Note ปัจจุบัน พร้อมการ์ด
- `/reference`: ค้นจากชื่อและเนื้อหา แต่ละผลแสดงเส้นทางใน Tree และบรรทัดแรกของเนื้อหากำกับเพื่อแยกชื่อซ้ำ การแทรกการ์ดไม่เปลี่ยน Parent หรือที่วางของ Note ที่ถูกอ้างอิง และมีข้อความแจ้งผู้ใช้
- `/link`: รับเฉพาะ URL เว็บ (ขึ้นต้น http/https) มีคำอธิบายว่า ถ้าจะเชื่อม Note ใน Jod ให้ใช้ `/reference` หรือ `/note`
- มือถือ: ใช้รายการลอยแบบ A ได้บนจอแคบ (ยังไม่ได้เลือกรูปแบบเฉพาะมือถือ แผงล่างแบบ C กินพื้นที่เกือบครึ่งจอ)

ยังไม่ได้ตัดสิน / ข้อสงสัยที่เหลือ (จาก ticket 020 และ 019):
- รูปภาพ (`/image`) เป็น Block ชนิดแยกหรือไฟล์แนบ และรูปภาพ/Callout อยู่ในรายการที่ AI ห้ามแตะ (013) หรือไม่
- prototype ใช้ข้อความสัญลักษณ์แทน Block จริง ยังไม่ได้ทดลองเมนู `/` ในบริบทของ Block ซ้อนกัน (List/Toggle) หรือใน Note ที่ยาวมาก
- เมนูบนแป้นพิมพ์มือถือจริง (การทดลองทำเฉพาะขนาดจอ ไม่ใช่เครื่องมือถือจริง)

โค้ด prototype เก็บที่ branch `prototype/slash-menu` (commit b20f636) ไม่รวมเข้า dev

- (อัปเดตภายหลัง 2026-10-18) กฎที่คงไว้และเพิ่มชัดเจน: ปิดเมนูแล้วข้อความเดิมต้องไม่หาย ผู้ใช้เขียนต่อจากตำแหน่งเดิมได้ และห้ามเพิ่มคำสั่ง AI หรือคำสั่งที่ทำลาย Block ลงในเมนูโดยไม่มีการตัดสินใจเพิ่มเติม
