## Question

AI Markdown Formatting (§14): AI จัดโครงสร้างเนื้อหาให้ผู้ใช้ทำอะไรได้บ้าง (เช่น เติมหัวข้อ จัดรายการ) โดย Block เป็นหน่วยจริง (006) "รักษาโครงสร้างเดิม" ตรวจอย่างไร: Block ไหนห้ามแตะ (Reference Card, ไฟล์, Code Block), ผลลัพธ์ของ AI ต้องผ่านผู้ใช้ยืนยันก่อนใช้ไหม และยกเลิกย้อนกลับได้ไหม

Options เดิมก่อนตัดสินใจ (เป็นข้อเสนอ ไม่ใช่ผลลัพธ์ ผลลัพธ์อยู่ใน Resolution):
- AI เสนอฉบับใหม่ ผู้ใช้เทียบและยืนยันก่อนแทนของเดิม
- Reference Card, ไฟล์, Code Block ห้าม AI แก้
- ข้อความเดิมของผู้ใช้ต้องไม่ถูกลบหรือเปลี่ยนความหมาย

## Resolution

ยืนยันโดยผู้ใช้

- AI ทำได้กว้าง: จัดหัวข้อ/รายการ/ชนิด Block, เรียบเรียงประโยค, สรุปย่อ (Q1 ข), เพิ่มเนื้อหาเสริม และแก้คำผิด (Q4)
- Reference Card, ไฟล์, Code Block, Link ห้ามแก้ (ข้อความเดิมว่า "ย้ายได้เฉพาะเมื่อจำเป็น" ถูกแทนที่แล้ว ดูอัปเดต 2026-10-18 ด้านล่าง)
- (แก้ภายหลัง จาก prototype 018: เดิมเป็น "เทียบแล้วยืนยันทั้งฉบับ") AI เสนอผลลัพธ์เป็นชุดการเปลี่ยนแปลงแบ่งเป็นรายการตาม Block ชนิดการเปลี่ยน: แก้ไข, เพิ่มใหม่, นำออก, แตกเป็นหลายส่วน, รวมเป็นส่วนเดียว, ย้ายตำแหน่ง ผู้ใช้เลือกรับฉบับ AI หรือเก็บฉบับเดิม **ทีละรายการ** (ไม่ต้องรับหรือปฏิเสธทั้ง Note) ค่าเริ่มต้นทุกรายการคือเก็บฉบับเดิม
- รายการที่ AI แตกเป็นหลายส่วนหรือรวมหลาย Block เป็นหนึ่งเดียว เลือกทั้งรายการ ไม่แยกเลือกย่อย
- ตัวเลือกต่างตามชนิด: เพิ่มใหม่ = รับ/ไม่รับ, นำออก = เก็บไว้/ยอมรับให้นำออก, อื่นๆ = ฉบับเดิม/ฉบับ AI
- มีปุ่มตั้งค่าทุกรายการพร้อมกัน (ใช้ฉบับ AI ทั้งหมด / เก็บฉบับเดิมทั้งหมด) เป็นแค่การตั้งตัวเลือก ปรับรายรายการต่อได้ ไม่ใช่การยืนยัน
- ต้องดูผลลัพธ์รวม (Preview) ก่อนยืนยัน ใน Preview สลับแต่ละรายการได้ ฉบับเดิมไม่ถูกแก้จนกว่าจะกดยืนยัน
- ระบบตรวจก่อนแสดงผล: Block ที่ห้ามแตะต้องยังครบและไม่ถูกแก้ ถ้าไม่ผ่านปฏิเสธผลลัพธ์ AI **ทั้งชุด** เก็บฉบับเดิมไว้ ไม่นำ Block อื่นจากชุดเดียวกันมาใช้ต่อเพราะอาจเกี่ยวข้องกัน และแจ้งผู้ใช้ว่า Block ไหนถูกแตะ
- ข้อสังเกต: เมื่อ AI เรียบเรียง/สรุปได้ กฎ "ข้อความเดิมต้องอยู่ครบทุกตัวอักษร" ใช้ไม่ได้ ส่วนที่ตรวจด้วยระบบได้จึงเป็นเรื่องโครงสร้างและ Block ที่ห้ามแตะ ส่วน "ไม่เปลี่ยนความหมาย" (§14) ตรวจโดยผู้ใช้ตอนเลือกรายรายการ
- เริ่มเมื่อผู้ใช้สั่งต่อ Note เท่านั้น ไม่ทำอัตโนมัติ
- (เพิ่มภายหลัง) ย้อนกลับฉบับเดิมได้หลังยืนยัน (Undo) ระยะเวลาเก็บฉบับก่อนแทนตัดสินตอน Architecture
- (เพิ่มภายหลัง) ข้อมูลที่ส่งให้ AI ตอนจัดโครงสร้าง ดู ticket 012
- (อัปเดตภายหลัง 2026-10-18) Protected Block เพิ่มเป็น 6 ชนิด: รูปภาพ, ไฟล์, Callout, Code, Reference Card, Link AI Formatting ต้องไม่แก้เนื้อหา เปลี่ยนชนิด ลบ **ย้ายตำแหน่ง** หรือปรับโครงสร้างของ Block เหล่านี้ (แทนกฎเดิมที่อนุญาตให้ย้ายเมื่อจำเป็น)
- (อัปเดตภายหลัง 2026-10-18) Toggle/List ที่มี Protected Block อยู่ข้างใน: AI จัดได้เฉพาะส่วนที่ไม่กระทบ Protected Block ขอบเขตของ "กระทบ" ดู `docs/open-questions.md` (OQ-1)
- (อัปเดตภายหลัง 2026-10-18) AI เสนอสร้าง Protected Block ใหม่ได้ ต้องให้ผู้ใช้ยืนยันก่อน (รายการเพิ่มใหม่ ค่าเริ่มต้น = ไม่รับ) การเพิ่มใหม่ไม่ถือเป็นการละเมิดที่ทำให้ทิ้งทั้งชุด
- (อัปเดตภายหลัง 2026-10-18) การป้องกันใช้กับการเปลี่ยนแปลงที่ AI Formatting เสนอเท่านั้น ผู้ใช้แก้เองได้ ไม่ได้ห้าม AI ฟีเจอร์อื่นทำงานกับ Block เหล่านี้ เว้นแต่มี Requirement ระบุ กฎรวมอยู่ที่ `docs/product-spec.md` หัวข้อ 4
- (อัปเดตภายหลัง 2026-10-18) ตัดสินแล้ว: "กระทบ Protected Block" = เปลี่ยนตำแหน่ง ลำดับ ระดับการซ้อน หรือ Parent ของ Protected Block และการเปลี่ยนชนิด/ลบ/แตก/รวมตัว Container (Toggle/List) ที่ครอบอยู่ AI แก้ข้อความของ Block ธรรมดาข้างๆ หรือข้างในได้ถ้าอยู่ตำแหน่งเดิม (กฎรวมที่ product-spec หัวข้อ 4)
