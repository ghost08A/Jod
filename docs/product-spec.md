# Jod — Product Spec

สรุปความต้องการที่ผู้ใช้ยืนยันแล้ว รวมจาก ticket 001-022 ใน `docs/wayfinder/` (ต้นฉบับ: `requirement.md`)
ศัพท์ทั้งหมดนิยามใน `CONTEXT.md` ถ้าสองไฟล์ขัดกัน ให้ถือ ticket ที่ปิดแล้วเป็นหลัก
ขอบเขต: Product Design เท่านั้น ยังไม่ลง DB / API / Code

## แนวคิดหลัก

- จดก่อน จัดทีหลัง / UX คล้าย Notion / Note ซ้อนเป็น Tree ไม่จำกัดความลึก / AI แนะนำ ผู้ใช้ตัดสิน
- แต่ละบัญชีเป็นพื้นที่ Note ของเจ้าของคนเดียว ไม่มีการแก้ไขร่วมกัน (Share = ดูอย่างเดียว)
- ใช้กับกลุ่มเพื่อน (กลุ่มปิด) ไม่ใช่บริการสาธารณะ
- "Topic" ไม่ใช่ศัพท์ของระบบ (ตัดทิ้งจาก §6)
- แพลตฟอร์ม: **Responsive Web เป็นแพลตฟอร์มหลักในระยะแรก** ออกแบบและทดสอบทั้งคอมพิวเตอร์และมือถือ มือถือต้องเขียนและใช้เมนู `/` ได้จริง ไม่ใช่แค่ย่อหน้าจอ Native App เป็นทางเลือกในอนาคต ไม่อยู่ในขอบเขตระยะนี้ (ticket 019) ธีมมืดเท่านั้น ไม่มีธีมสว่าง

## 1. Note, Editor, Autosave (§1, §2, §4, §12)

- ทุก Note มี Title (แก้ได้ Inline), Block หลายอัน และ Context ของตัวเอง
- Block เป็นหน่วยจริงของเนื้อหา Markdown เป็นแค่นำเข้า/ส่งออก
- ชนิด Block: Paragraph, Heading, Bullet List, Numbered List, Checklist, Toggle, Quote, Code, Divider, Link (URL ภายนอก), Reference Card (ชี้ Note ภายใน), **ไฟล์** (ใหม่), **รูปภาพ** (Block ชนิดแยก ไม่ใช่ Block ไฟล์ แม้อาจอ้างไฟล์รูปที่จัดเก็บผ่านระบบแนบไฟล์) และ **Callout** (Block ชนิดแยก) Heading มี 3 ระดับ (ticket 020)
- List, Checklist, Toggle ซ้อนได้ไม่จำกัดชั้น ใส่ Block ชนิดไหนไว้ข้างในก็ได้
- Autosave เมื่อหยุดพิมพ์ ~1 วินาทีและเมื่อออกจากหน้า แสดงสถานะ กำลังบันทึก / บันทึกแล้ว / บันทึกไม่สำเร็จ (ไม่สำเร็จ = เนื้อหายังอยู่ในจอ ลองใหม่ได้)
- บันทึกชนกัน (เช่น สองแท็บ): แจ้งทันที เลือก ใช้ฉบับนี้ / ใช้ฉบับอีกแท็บ / เก็บทั้งสอง (อีกฉบับเป็น Unplaced note ใหม่)
- Context เป็นช่องแยกจากเนื้อหา ผูกกับ Note เดียว ไม่สืบทอดไป Child

## 2. จดและจัดวาง (§3, §5, §7)

- ปุ่ม New note มีปุ่มเดียว อยู่หน้าแรกเท่านั้น สร้างได้ทันทีไม่ต้องตั้งชื่อ (Title เริ่มต้นเป็นข้อความคงที่ ไม่เปลี่ยนเอง)
- กด Save เลือก: ให้ AI จัดให้ / เป็นแม่ใหม่ (Root note) / ปล่อยเป็น Unplaced note ปิดโดยไม่เลือก = Unplaced
- Note ที่สร้างจากปุ่ม New note แล้วว่างเปล่าและ Title ยังเป็นค่าเริ่มต้น ถูกลบถาวร ไม่ผ่าน Trash
- `/Note` ใน Editor = สร้าง Child พร้อมการ์ดทันที ไม่มี Save ไม่ถูกลบอัตโนมัติ
- Unplaced note อยู่ในพื้นที่ "รอจัดวาง" แยกจาก Tree ออกจากรายการเมื่อจัดวางแล้ว
- Parent/Child เป็นอิสระจาก Reference Card
- ย้าย Note = ย้ายทั้งกิ่งเสมอ ห้ามย้ายเข้าตัวเองหรือลูกหลาน ลำดับ Child ผู้ใช้จัดเอง (ใหม่ต่อท้าย) ย้ายออกมาระดับบนสุดได้ = Root note
- Breadcrumb, พับ/ขยาย Tree ตาม §3

## 3. AI Placement (§7, §13)

- AI ทำงานเมื่อผู้ใช้สั่งเท่านั้น (ตอน Save หรือกดขอจาก Unplaced note)
- เสนอ Suggestion ตัวเดียว จาก Note ที่มีอยู่ (รวม Root note) ไม่เสนอสร้างแม่ใหม่ ถ้าไม่มีที่เหมาะบอกว่า "ไม่พบที่เหมาะสม"
- ยืนยัน = ย้ายทันที (ต่อท้ายลูกเดิม) / ปฏิเสธ = ยังเป็น Unplaced ไม่เสนอที่เดิมซ้ำ
- Suggestion ไม่หมดอายุ ไม่วิเคราะห์ซ้ำเอง แก้เนื้อหาแล้วขึ้น "อาจล้าสมัย"
- Parent ที่เสนอถูกลบ = Suggestion หาย / ถูก Merge = ตาม Alias
- รายการ "รอจัดวาง" มีเครื่องหมายและกรองเฉพาะที่มี Suggestion ได้

## 4. AI Markdown Formatting (§14)

- ทำเมื่อผู้ใช้สั่ง ทำได้กว้าง: จัดหัวข้อ/รายการ/ชนิด Block, เรียบเรียง, สรุป, เพิ่มเนื้อหาเสริม, แก้คำผิด
- **Protected Block** (6 ชนิด): รูปภาพ, ไฟล์, Callout, Code, Reference Card, Link AI Formatting ต้องไม่แก้เนื้อหา เปลี่ยนชนิด ลบ **ย้ายตำแหน่ง** หรือปรับโครงสร้างของ Block เหล่านี้
- Toggle/List ที่มี Protected Block อยู่ข้างใน: AI จัดได้เฉพาะส่วนที่ไม่กระทบ Protected Block "กระทบ" = เปลี่ยนตำแหน่ง ลำดับ ระดับการซ้อน หรือ Parent ของ Protected Block และการเปลี่ยนชนิด/ลบ/แตก/รวมตัว Container (Toggle/List) ที่ครอบอยู่ AI แก้ข้อความของ Block ธรรมดาข้างๆ หรือข้างในได้ถ้าอยู่ตำแหน่งเดิม
- AI เสนอสร้าง Protected Block ใหม่ได้ แต่ต้องให้ผู้ใช้ยืนยันก่อน (เป็นรายการ "เพิ่มใหม่" ค่าเริ่มต้น = ไม่รับ) การเพิ่มใหม่ไม่ถือเป็นการละเมิดข้อห้ามข้างต้น
- การป้องกันใช้กับการเปลี่ยนแปลงที่ AI Formatting เสนอเท่านั้น ผู้ใช้แก้ Protected Block เองได้ตามความสามารถของ Editor และกฎนี้ไม่ได้ห้าม AI ฟีเจอร์อื่นทำงานกับ Block เหล่านี้ เว้นแต่มี Requirement ระบุ
- AI เสนอผลลัพธ์เป็นชุดการเปลี่ยนแปลงรายการตาม Block (แก้ไข, เพิ่มใหม่, นำออก, แตกเป็นหลายส่วน, รวมเป็นส่วนเดียว, ย้ายตำแหน่ง) ผู้ใช้เลือกรับฉบับ AI หรือเก็บฉบับเดิมทีละรายการ ค่าเริ่มต้น = เก็บฉบับเดิม
- รายการแตกเป็นหลายส่วน/รวมหลาย Block เลือกทั้งรายการ ไม่แยกเลือกย่อย
- ปุ่ม "ใช้ฉบับ AI ทั้งหมด" / "เก็บฉบับเดิมทั้งหมด" เป็นแค่ตั้งตัวเลือก ต้องดู Preview ผลลัพธ์รวมก่อนยืนยัน ฉบับเดิมไม่ถูกแก้จนกว่ากดยืนยัน ย้อนกลับได้ (Undo)
- ระบบตรวจก่อนแสดงผล: ถ้า AI พยายามแก้ Protected Block ที่มีอยู่ ปฏิเสธผลลัพธ์ทั้งชุด เก็บฉบับเดิมไว้ทั้งหมด แจ้งผู้ใช้ว่า Block ใดไม่ผ่านการตรวจ (หากระบุได้) ห้ามนำผลลัพธ์ที่ไม่ผ่านไปใช้กับ Note ต้นฉบับ ไม่ใช้ Block อื่นจากชุดเดียวกัน "ไม่เปลี่ยนความหมาย" ผู้ใช้ตรวจเองตอนเลือกรายรายการ

## 5. ข้อมูลที่ส่งให้ AI

- จัดวาง: Title+เนื้อหา+Context ของ Note ที่วิเคราะห์ และ Title+Context ของ Note ที่เป็นที่วางได้
- จัดโครงสร้าง: Title+เนื้อหา+Context ของ Note นั้นเท่านั้น
- แจ้งผู้ใช้ครั้งแรกที่ใช้ AI และปุ่ม AI บอกชัดว่าจะส่งอะไร ไม่มีเครื่องหมาย "ห้าม AI เห็น" ใน v1

## 6. Search (§6)

- ค้นชื่อ + เนื้อหา (ไม่ค้น Context) รวม Unplaced ไม่รวม Trash (ค้นใน Trash แยก)
- Filter ตาม Parent รวมลูกหลานทั้งกิ่ง

## 7. Trash (§8)

- ลบ: เลือก "ทั้งกิ่ง" (ค่าเริ่มต้น) หรือ "เฉพาะ Note นี้" (ลูกขึ้นไปใต้ Parent ของมัน Root note → ลูกเป็น Root note)
- กู้ที่แม่ของกิ่ง = กู้ทั้งกิ่ง / กู้ลูกเดี่ยวหรือ Parent เดิมไม่มี = Unplaced note / กู้ A ที่ลบแบบเฉพาะตัว = กลับใต้ Parent เดิมต่อท้าย ลูกเดิมไม่ย้ายกลับ
- ลบถาวรผู้ใช้สั่งเอง พร้อมยืนยัน ไม่มีกวาดอัตโนมัติ
- Note ใน Trash เปิดดูได้อย่างเดียว การ์ดที่ชี้แสดง "ถูกลบ" (กู้ได้) หลังลบถาวรแสดง "ไม่พบ Note นี้"

## 8. Merge และ Reference (§5, §9)

- การ์ดชี้ตัวตน Note ไม่ใช่ตำแหน่ง ย้ายแล้วไม่เสีย
- การ์ดแสดงชื่อ Note และชื่อ Parent ตัวสุดท้ายตัวเล็กๆ ใต้ชื่อเสมอ (Note ที่ยังไม่จัดวางแสดง "รอจัดวาง") เพื่อแยก Note ชื่อซ้ำ
- Merge A เข้า B (ผู้ใช้เลือกปลายทาง): เนื้อหา A ต่อท้าย B, Child ของ A ย้ายไป B, ใช้ Title/Context ของ B, ไฟล์ตามเนื้อหา, Title เดิมของ A เก็บเป็น Alias
- ย้อนกลับไม่ได้ ต้องเตือนว่า "Context ของ A จะหายไป"
- Alias ต่อทอดได้ (A→B→C) ปลายทางอยู่ใน Trash = หน้า "อยู่ใน Trash" พร้อมกู้

## 9. Attachments (§15)

- ไฟล์เป็น Block ใน Note จึงเป็นของ Note เดียว ตาม Note เมื่อ Trash/กู้/ลบถาวร/Merge
- มีขีดจำกัดชนิด/ขนาด บอกผู้ใช้ชัดเมื่อเกิน (ตัวเลขตัดสินตอน Architecture)
- ไฟล์ภาพของ Block รูปภาพ: ลบจริงเมื่อไม่มี Block ใดอ้างถึงแล้ว นับรวม Block ใน Note ที่อยู่ใน Trash, ฉบับก่อน AI แทน (Undo) ที่ยังเก็บอยู่ และ Note ที่ถูก Merge ไปแล้ว ขนาดไฟล์ภาพยังไม่กำหนดตัวเลข (OQ-3)

## 10. Share Link (§16)

- แชร์ Note พร้อมลูกหลานทั้งกิ่ง ดูอย่างเดียว ต้องมี email ที่ยืนยันแล้วถึงสร้างได้
- เลือก: ใครมี Link ก็ดูได้ หรือ จำกัดด้วย email (ผู้รับ Login ด้วยบัญชีที่ email ตรงและยืนยันแล้ว ก่อนผ่านไม่เห็นเนื้อหาหรือชื่อ)
- เพิกถอนได้ทุกเมื่อ ตั้งวันหมดอายุได้ (ค่าเริ่มต้นไม่หมดอายุ)
- การ์ดใน Note ที่แชร์: ผู้รับเปิด Note ปลายทางพร้อมลูกหลานได้ และตามต่อไปได้ ผู้แชร์ต้องรู้เอง
- ย้าย = Link ใช้ต่อ / ลบ = ใช้ไม่ได้ กู้แล้วใช้ได้อีก / Merge = ใช้ไม่ได้
- ของใหม่เข้ากิ่งที่แชร์ (ย้ายเข้า, Merge เข้า, ลูกใหม่, กู้คืน) ถูกแชร์อัตโนมัติ Note ใต้กิ่งที่แชร์มีเครื่องหมาย "แชร์อยู่ผ่าน Link ของ …" และเตือนก่อนย้าย/Merge เข้า

## 11. Account และ Email (§11)

- สมัครด้วย email + รหัสผ่าน ลืมรหัสผ่านผ่านลิงก์ทาง email ทุกบัญชีมีพื้นที่ Note ของตัวเอง (รวมผู้รับ Link ที่สมัครมา)
- ยังไม่ยืนยัน email: จด/จัดวาง/ค้นหา/ใช้ AI ได้ปกติ แต่สร้าง Share Link ไม่ได้
- ขอส่งยืนยันใหม่ได้ ลิงก์มีอายุจำกัด จำกัดจำนวนครั้งต่อช่วงเวลา เปลี่ยน email ไม่ได้ใน v1

## 12. Error Logging (§10)

- ผู้ใช้เห็นข้อความเข้าใจง่าย + รหัสอ้างอิง ไม่เห็นรายละเอียดภายใน
- log เก็บว่าเกิดอะไร เมื่อไร ที่ไหน + รหัสอ้างอิง ไม่เก็บเนื้อหา Note/Context/ชื่อไฟล์/email/รหัสผ่าน/token
- AI ใช้ไม่ได้: Note ที่ Save ไว้ปลอดภัยเสมอ เป็น Unplaced แจ้งผู้ใช้ ลองใหม่ได้

## 14. เมนู / (Slash commands) (ticket 020)

- ข้อความและโครงสร้าง: /text, /h1, /h2, /h3, /bullet, /numbered, /todo, /quote, /divider
- Note และลิงก์: /note (สร้างลูกพร้อมการ์ด), /reference (ค้น Note ที่มีแล้วแทรกการ์ด ไม่สร้างลูก ไม่เปลี่ยน Parent), /link (URL ภายนอกเท่านั้น)
- เนื้อหาพิเศษ: /code, /image, /file, /toggle, /callout
- รูปแบบเมนู (ticket 021) **Variant A เป็นรูปแบบสุดท้าย**: รายการลอยใต้บรรทัดที่พิมพ์ แบ่งตามหมวด พิมพ์ต่อเพื่อกรอง /note สร้างทันที (กฎ 002 ไม่เปลี่ยน) /reference ค้นพร้อมแสดงเส้นทางใน Tree
- ปิดเมนูแล้วข้อความเดิมต้องไม่หาย ผู้ใช้เขียนต่อจากตำแหน่งเดิมได้
- ห้ามเพิ่มคำสั่ง AI หรือคำสั่งที่ทำลาย Block ลงในเมนูโดยไม่มีการตัดสินใจเพิ่มเติม
- มือถือ: เมนูต้องใช้ได้จริงกับแป้นพิมพ์มือถือ ผลทดสอบ prototype (ticket 022): ส่วนที่ทดสอบได้ผ่านแล้ว Nested Blocks, การแตะจริง และแป้นพิมพ์มือถือจริงเป็นเกณฑ์ตรวจรับของ Editor จริง

## 15. ข้อกำหนดที่ไม่ใช่ฟังก์ชันและข้อจำกัดทางเทคนิค (ตัดสินแล้ว 2026-10-18)

- กลุ่มผู้ใช้และขนาด: กลุ่มเพื่อน เป้าหมายไม่เกินหลักพันบัญชี ไม่เกินหลักหมื่น Note ต่อบัญชี (เลือกสิ่งที่ขยายทีหลังได้ ไม่ปิดทางโต)
- ต้องออนไลน์ใน v1 ไม่มีโหมดออฟไลน์ (บันทึกไม่สำเร็จ = เนื้อหายังอยู่ในจอ ลองใหม่ได้ ตาม ticket 007)
- เทคโนโลยีที่กำหนดแล้ว: .NET 8 (หลังบ้านตามฐานที่มี) และ React + TypeScript (หน้าบ้าน) รันบน Docker, TipTap เป็นฐานของ Editor และเมนู `/` (ADR 0003), ที่เก็บไฟล์และรูปผ่าน S3 API มาตรฐานด้านหลัง Interface โดยยังไม่เลือกตัวที่เก็บจริง (ADR 0001)

## 13. ทิศทาง UX (ผลจาก prototype ticket 017)

- workspace: แถบข้างซ้าย (New note, Tree, รอจัดวาง) + canvas เขียนโล่ง Title/เนื้อหาพื้นเดียวกัน ไม่มีกรอบ การ์ด เส้นแบ่ง หรือแถบล่าง
- Layout (จอกว้าง): แถบข้าง ~300px, เนื้อหา max ~600px ชิดซ้าย, Title ใหญ่ เว้นด้านบนมาก ธีมมืดเท่านั้น แถบข้างซ่อน/แสดงได้ Title เริ่มต้น "Untitled" ข้อความเนื้อหาในธีมมืดไม่ลดความสว่าง
- มือถือ: ต้องมี layout แยกสำหรับ Responsive Web (ยังไม่ได้ออกแบบ ดู ticket 019)
- Note ใหม่: เขียนได้ทันที เคอร์เซอร์อยู่ในเนื้อหา การจัดวางเป็นปุ่มเล็กมุมขวาบน (เมนูลอย) ไม่ขวางการเขียน
- ดูรายละเอียดและเหตุผลที่ `docs/wayfinder/tickets/017-prototype-capture-home.md` ต้นแบบอยู่ branch `prototype/capture-home`
- หน้าตรวจผล AI จัดโครงสร้าง (018): เทียบซ้าย-ขวา (Side-by-side) มีแถบเลือกเหนือแต่ละ Block ที่เปลี่ยน ปุ่มตั้งค่าทุกรายการพร้อมกัน และ Preview ผลลัพธ์รวมก่อนยืนยัน หน้าบันทึกชนกันใช้ Side-by-side เหมือนกัน (บนมือถือต้องมีทางสำรองเพราะแคบเกินไป)
